# Real mkmk runs four phases by default (framework identity-card processing, public-header-list generation, module build-file check/update, the build itself) and exposes CLI options controlling target scope, parallelism, and build variants

Default no-argument invocation processes all four phases for the current directory's scope. Scope is inferred from the current working directory (workspace root / framework dir / module dir) combined with optional positional arguments (framework name(s), module name(s), or an 'all under here' flag), with documented rules for what combinations are valid or erroneous. Notable options: parallel job count, verbose command echo, debug vs. optimized compile mode, warnings-as-errors-off mode, force-refresh of generated build metadata without rebuilding, and identity-card-only / no-identity-card-recompile modes. Pure context for later CLI spec work -- not yet a requirement.
