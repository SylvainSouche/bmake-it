# Empirically confirmed: TARGET=/TARGET_ARCH= have ZERO effect on the actual compiler invoked for a standalone bsd.prog.mk-based project (outside FreeBSD base-system buildworld/Makefile.inc1 infrastructure). Setting TARGET_ARCH=arm64 on an amd64 host still produced a plain x86-64 binary

Test performed: minimal PROG=hello module, .include <bsd.prog.mk>, built against real FreeBSD share/mk with 'bmake TARGET=freebsd TARGET_ARCH=arm64' on an amd64 host. Result: CC resolved to plain 'cc' (unchanged), and 'file hello' confirmed the resulting binary is genuinely x86-64 ELF, NOT arm64 -- TARGET_ARCH was silently ignored for cross-compiler selection purposes. This directly and unambiguously CONFIRMS the risk flagged as Tier 1.1 in the validation plan (spec/60-bsd-make-validation-plan.md): TARGET=/TARGET_ARCH= are tied to FreeBSDs base-system cross-build machinery (Makefile.inc1/src.conf/buildworld), which a standalone bsd.prog.mk/bsd.lib.mk-based project outside the FreeBSD source tree does not have, so plain share/mk alone does not implement cross-compiler selection from these variables. This is the single highest-impact finding of the validation pass.
