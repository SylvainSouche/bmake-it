# Empirically confirmed: bsd.dep.mk's automatic depend: wiring does not do real work in either readily-available lineage -- modern FreeBSD requires meta-mode/filemon or DIRDEPS_BUILD infrastructure not present standalone; NetBSD's bundled version is a literal no-op (rm -f .depend; touch .depend). The underlying mkdep TOOL itself, called directly, produces correct transitive header dependencies

Test performed: `bmake depend` against real FreeBSD share/mk on a minimal PROG=hello module (SRCS=main.c greet.c, greet.c including greet.h) produced only a single link-level line (hello.full: /usr/lib/libc.a) -- no header dependency tracking at all. Source inspection confirmed bsd.dep.mk contains zero references to mkdep; its real logic is gated behind meta-mode (_meta_filemon, kernel-level syscall tracing) or MK_DIRDEPS_BUILD, both deeply tied to FreeBSD's base-system build infrastructure (Makefile.inc1-adjacent), not present or meaningful for a standalone project. Separately, NetBSD's own bundled bsd.dep.mk (shipped inside the portable bmake Debian package, self-consistent with its own make binary) was checked directly: its entire .depend: rule is `rm -f .depend; touch .depend` -- a no-op that produces an empty file, no real dependency data whatsoever. HOWEVER: calling `mkdep -f .depend main.c greet.c` directly (bypassing bsd.dep.mk's depend: target entirely) produced complete, correct, transitive per-source-file header dependencies, correctly including greet.h and the full system header chain. Conclusion: the underlying dependency-scanning CAPABILITY (mkdep the tool) works correctly; what does not work, in either lineage as tested here, is the automatic "just .include <bsd.dep.mk> and typing make depend produces useful output" assumption REQ-mkdep-style-header-dependency-tracking-req rested on.

**CORRECTION (see OBS-validation-compiler-native-md-dependency-tracking-confirmed):** this test examined the `depend:` target and the aggregate `.depend` file specifically, and its narrow factual claims about those two things remain accurate. But it drew the wrong overall conclusion, because it wasn't the mechanism that actually matters -- real `bsd.sys.mk` separately wires the compiler's own `-MD` flag into every ordinary compile, producing correct per-object `.depend.<obj>` files automatically, with no `make depend` step needed at all. That mechanism is confirmed fully working. Do not rely on this OBS's conclusion; see the correcting one instead.
