# mkmk supports static (copy) and dynamic (search-path) access to prerequisite frameworks across a list of workspaces

Two companion commands manage cross-workspace prerequisites in real mkmk: one defines a dynamic search path of parent-workspace roots that mkmk consults at build time (ordered, most-preferred first, falls through to the next if a framework isn't found in the first); the other physically copies (a subset of) prerequisite framework data into the local workspace instead, trading dynamic reactivity for isolation/stability. This directly reinforces REQ-workspace-parent-search-order (ordered fallback search across parent workspaces), and adds a design choice not yet decided for our system: do we want both a 'static copy' and a 'dynamic search path' mode, or just one of them?
