# Empirically confirmed: DEBUG_FLAGS is genuinely bsd-make-native -- bsd.debug.mk appends it to CFLAGS/CXXFLAGS, and its presence/absence also toggles default binary stripping (STRIP defaults to -s, stripping, only when DEBUG_FLAGS is unset). COPTFLAGS is NOT the optimization-level variable in real FreeBSD share/mk -- that specific naming guess was wrong; the actual default -O2 traces elsewhere (not fully identified in this pass)

Test performed: queried bmake -V CFLAGS, -V DEBUG_FLAGS, -V COPTFLAGS against a minimal bsd.prog.mk-based module. Source inspection of bsd.debug.mk and bsd.own.mk confirms DEBUG_FLAGS is a real, coherent mechanism: when defined, it is appended to CFLAGS/CXXFLAGS (bsd.debug.mk) and suppresses default automatic symbol stripping (bsd.own.mk: STRIP?=-s only fires when DEBUG_FLAGS is NOT defined). This CONFIRMS the DEBUG_FLAGS half of REQ-debug-release-via-native-bsd-flags-req -- no correction needed there. However, COPTFLAGS evaluated to empty and is not the mechanism behind the -O2 seen in default CFLAGS output -- that specific variable-name guess from the original REQ is not confirmed correct; the actual optimization-level variable was not conclusively identified in this pass (not CFLAGS itself either, per bsd.sys.mk inspection -- likely set even further upstream in sys.mk or via a compiler-detection mechanism). This narrower point remains open, to be finished on a real FreeBSD box per the original follow-up.
