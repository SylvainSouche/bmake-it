# Real mkmk headers have four visibility levels (framework-level Public/Protected/Private, module-level Local), each in its own directory, with build-time checks on cross-level and cross-framework includes

Framework-level header directories: one for headers exposed to any consumer, one for headers exposed only within an internal circle of frameworks, one for headers visible only within the framework's own modules. A fourth, module-level directory holds headers private to a single module. Build-time checks enforce that a header at a given level may only include headers at the same level or above, and that cross-framework includes are only allowed against a directly-declared prerequisite. CONFLICT with REQ-framework-header-exposure, which currently describes a simpler two-level model (one public include dir, one module-local include dir). Needs a decision: adopt the full four-level model, or keep the simpler two-level one.
