# share/ staging is a layered overlay copy (common, then os, then os_arch, each overwriting same-named files from the previous layer), not a pick-one-directory selection

User clarified the staging mechanism for REQ-share-dir-fallback-hierarchy: it is not a pick-the-single-most-specific-directory-and-ignore-the-rest selection. Instead, staging copies share/common/ first, then copies share/<os>/ on top (overwriting any same-named files from common/), then copies share/<os>_<arch>/ on top of that (overwriting any same-named files from the previous two layers). Files that exist only at one level simply pass through untouched; files that exist at multiple levels end up as the most specific version, but the other levels still contribute whatever they uniquely provide. This is an overlay/merge, not an either-or selection between whole directories.
