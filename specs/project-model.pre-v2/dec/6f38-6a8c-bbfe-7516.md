# Convenience make targets add-prereq and add-parent append entries to PREREQS= and PARENT_WS= respectively, editing the makefile text directly, rather than requiring hand-editing

User confirmed wanting convenience targets for a common, easy-to-get-wrong task: appending a new entry to a framework makefiles PREREQS= (REQ-framework-prereqs-macro-req, REQ-prereqs-mandatory-even-empty-req) or a workspace makefiles PARENT_WS= (REQ-workspace-parent-macro-absolute-req). Proposed invocation shape: make add-prereq FW=System (run from within a framework directory, appends System to that frameworks PREREQS=) and make add-parent WS=/abs/path (run from the workspace root, appends the path to PARENT_WS=). This is distinct from and does NOT reopen NREQ-no-copy-preq-commands, which rejected mkGetPreq/mkCopyPreq-style search-path RESOLUTION commands -- these new targets are narrow text-editing convenience only, they do not resolve, copy, or search for anything, just mutate the relevant macro in the makefile.
