# Build outputs are organized as build/$OS_ARCH/{obj,bin,lib,...} at module, framework, AND workspace levels, not just module level

User specified a layered scheme: every level of the hierarchy (module, framework, workspace) has its own build/$OS_ARCH/ directory, containing subdirectories for different kinds of output (obj for intermediate objects, bin/lib for linked artifacts, etc.). This supersedes the earlier, module-only obj/<OS_ARCH>/ requirement. Since $OS_ARCH keys the whole build/ subtree at every level, multiple targets can be built into the same source tree side by side without collision -- this is the mechanism satisfying the cross-compile requirement. Exact aggregation mechanism (how a framework's build/$OS_ARCH/lib gets populated from its modules' outputs -- copy vs symlink vs build-directly-there) is not yet decided, follow-up question pending.
