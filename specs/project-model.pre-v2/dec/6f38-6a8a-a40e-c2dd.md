# A frameworks build order across the workspace is determined by the dependency graph implied by all frameworks PREREQS declarations: a framework is only built after every framework it lists in PREREQS has finished building

User confirmed this is not optional: build order HAS TO follow the PREREQS dependency graph, because a framework genuinely needs its prereqs build OUTPUT to exist before it can build itself -- specifically (a) linking against a prereqs libraries requires that prereqs build/<KEY>/lib/ to already be populated (REQ-workspace-build-sequence-req), and (b) resolving a prereqs PROMOTED PUBLIC generated headers requires that prereqs build/<KEY>/include/ to already be populated (REQ-generated-headers-in-build-tree-req) -- unlike hand-written headers, which are pure source and impose no such ordering requirement. This is a workspace-wide topological build order across all frameworks, distinct from the earlier, narrower decision about within-one-frameworks PREREQS list ordering mattering for header search-path priority (REQ-framework-prereqs-macro-req). Actual cycle handling remains unspecified -- consistent with REQ-prereqs-misorder-no-validation-req (do nothing for now), a genuine dependency cycle across frameworks has undefined/unhandled behavior at this stage.
