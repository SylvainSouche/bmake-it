# Packaging for distribution is a separate make target producing native OS install packages (msi, pkg, deb, rpm, ...), not run as part of the default build

User wants a distinct make target (e.g. something like 'make package' or 'make install', exact name TBD) that is NOT part of the default build steps, dedicated to producing deployment/installer packages in native per-OS formats: .msi (Windows/Cygwin? -- open question since Windows is Cygwin/WSL-only per REQ-windows-hosts-cygwin-wsl), .pkg (macOS), .deb and .rpm (Linux), and presumably a ports-style package for *BSD (mentioned generically as 'ports' earlier but not yet confirmed for the packaging step specifically). This goes beyond a generic tarball -- real per-platform installers/package formats are wanted.
