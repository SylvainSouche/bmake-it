# Per-module compile/link flags reuse bsd makes own native CFLAGS/CXXFLAGS/LDFLAGS/YFLAGS/LFLAGS variables directly (appended via += in the module makefile); no new LOCAL_*FLAGS-style wrapper macros are introduced

User chose to reuse bsd makes native flag variables directly rather than mirror real mkmks own LOCAL_CFLAGS/LOCAL_CCFLAGS/LOCAL_YFLAGS/LOCAL_LFLAGS/LOCAL_LDFLAGS convention (OBS-mkmk-module-buildfile-macros). This matches the pattern already used for TARGET=/TARGET_ARCH= (REQ-target-selection-uses-bmake-native-vars-req), DESTDIR/PREFIX (REQ-destdir-prefix-confirmed-req), and DEBUG_FLAGS/optimization flags (REQ-debug-release-via-native-bsd-flags-req): wherever bsd make already provides a native variable for something, reuse it as-is instead of inventing a project-specific wrapper. A module needing extra compile or link options (per REQ-module-makefile-fields original wording, additional compilation or link options) simply appends to CFLAGS/CXXFLAGS/LDFLAGS/YFLAGS/LFLAGS in its own makefile using ordinary += syntax.
