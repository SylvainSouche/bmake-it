# Standard bsd make mkdep-style per-source .depend header dependency tracking is in scope, distinct from the PARENT_WS/PREREQS resolution cache: touching a header only triggers recompilation of the .o files that actually (transitively) include it

User confirmed file-level header dependency tracking is wanted now, using the standard bsd make mkdep/.depend mechanism: for each module, a generated .depend file records which source files include which headers (transitively), consumed via .include so make can decide per-.o-file whether recompilation is needed when a header changes. This is explicitly a DIFFERENT concern and likely a different generated file from the PARENT_WS/PREREQS resolution cache (REQ-prereqs-resolution-cached-like-depend-req) -- that one caches workspace/framework-level dependency-graph resolution, this one caches module-level, per-source-file header include relationships for incremental compilation. Both happen to reuse the same general bsd-make .depend idiom (generated file, .included, regenerated via an explicit or detected-stale step) but serve different purposes at different levels.
