# Windows is in scope only via Cygwin or WSL, not as a native MSVC/cl.exe host

User confirmed Windows support means running under Cygwin or WSL -- both POSIX-like layers atop Windows -- rather than a native Windows build host with MSVC/cl.exe and its own naming conventions. This effectively makes Windows a fourth *NIX-like build host alongside macOS, Linux, and *BSD: bsd make, gcc/llvm, and *NIX naming conventions apply (WSL is genuinely Linux; Cygwin provides a Unix-like environment/naming, e.g. still typically produces .exe but otherwise behaves like a POSIX host). No native Windows toolchain (MSVC), no dllexport/dllimport macro pattern, no COM type-library import -- those real-mkmk mechanisms (see OBS-mkmk-java-and-windows-specifics) stay out of scope.
