# Compound target key string format is <os>-<arch>-<toolchain>, e.g. macosx-arm64-llvm; arm64/amd64 architecture granularity confirmed sufficient for phase 1, no finer ISA sub-variant needed

User confirmed the target-key string format <os>-<arch>-<toolchain> (e.g. macosx-arm64-llvm) as the naming scheme for REQ-target-key-includes-toolchain, and raised whether the arch label granularity (arm64) is sufficient to cover all ISA variants. Discussed and confirmed: for phase 1 (REQ-phase1-concrete-targets), arm64 is a single uniform ISA baseline across all Apple Silicon chips (no sub-variant split needed), and FreeBSD/x64 should use FreeBSD's own native architecture name amd64 rather than x64/x86_64, so autodetection can match uname -m/-p output directly. Finer CPU-generation tuning is a compile-flag concern (e.g. -mcpu-style flags), not a separate build-tree target -- it does not get its own directory, the same way build variant does not (REQ-variant-out-of-scope-for-dirtree).
