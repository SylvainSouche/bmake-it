# Windows (win) target output can be produced via a mingw-w64-style cross-compilation toolchain from any capable build host (not exclusively from within Cygwin); WSL is confirmed to fold into the linux build host, not a distinct win-producing host; exact mingw-vs-Cygwin toolchain distinction for win targets is deferred

User correctly identified that mingw-w64-style cross-compilers can run on any Linux host (including WSL, itself just Linux) to produce genuine native Windows PE binaries with no runtime dependency on cygwin1.dll -- a fully distinct path from Cygwins own native gcc (which produces PE binaries that DO depend on cygwin1.dll at runtime, with Cygwins own naming/versioning conventions). This reinforces the already-decided toolchain/host separation (REQ-target-key-includes-toolchain): producing a win target does not require running the build from inside Cygwin specifically -- it can be cross-compiled from any host (Linux/WSL, macOS, FreeBSD) using a mingw-w64-class toolchain, the same way any other cross-compile target works. Given win is not in the phase-1 target list at all (REQ-phase1-concrete-targets), and the user explicitly had not looked closely at this yet, the exact mingw-vs-Cygwin toolchain distinction (naming, which one is default, whether both are supported, runtime dependency implications) is deferred -- joining the existing list of later items (OpenBSD/NetBSD, per-distro Linux, kernel/Darwin dev, .app bundles).
