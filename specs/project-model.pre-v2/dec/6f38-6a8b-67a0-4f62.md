# TOOLCHAIN=<name> triggers .include of a dedicated toolchain mk file (e.g. mk.toolchain.gcc.mk / mk.toolchain.llvm.mk) that sets the underlying CC/CXX/LD/AR/AS choices, consistent with the projects existing role-specific .mk file pattern

User confirmed the mechanism (a refinement of the preset option from DEC-toolchain-cli-variable, made concrete): rather than inline conditional logic keyed off TOOLCHAIN=, the value selects and .includes a dedicated toolchain .mk file that decodes the full set of underlying tool choices (CC, CXX, LD, AR, AS, and presumably ABI-related settings for platforms where that matters). This mirrors the projects existing pattern of role-specific included files (mk.workspace.mk, mk.framework.mk, mk.prog.mk, mk.lib.mk -- REQ-uniform-makefile-filename-req) rather than introducing a different mechanism just for toolchain selection. As with any bsd make variable, the underlying CC/CXX/LD/AR/AS variables set by the toolchain mk file remain individually overridable afterward using normal make variable-precedence rules.
