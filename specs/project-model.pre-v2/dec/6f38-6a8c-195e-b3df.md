# Packaging targets (make port, make pkg, etc.) stage into a distrib/<KEY> directory at workspace root, parallel to build/<KEY>, rather than an arbitrary temporary DESTDIR or working directly from build/<KEY>

Resolves the open install-vs-packaging relationship question. Rather than packaging targets either working straight from build/<KEY>/ or invoking install into some transient/anonymous temp directory, there is a persistent, well-known workspace-level distrib/<KEY>/ directory (sibling to build/<KEY>/, same target-key scheme -- REQ-target-key-omit-defaults-req) that packaging targets populate as their staging area, mirroring an install-prefix layout (the same shape as REQ-destdir-prefix-confirmed-reqs DESTDIR staging, just given a fixed, in-tree, inspectable location instead of a throwaway temp dir). The actual per-format package artifact (a .pkg, a port skeleton, a .deb, etc.) is then built FROM this staged distrib/<KEY>/ tree. This effectively answers the make-install-vs-packaging question: packaging likely uses the same staging mechanism as install (DESTDIR-style), just pointed at distrib/<KEY>/ instead of an arbitrary destination -- exact invocation (whether packaging literally calls make install DESTDIR=distrib/<KEY> internally, or uses a related-but-separate mechanism) is a minor open follow-up.
