# SHLIB_MAJOR/SHLIB_MINOR is the single cross-platform source of truth for library versioning; mk.lib.mk emits the appropriate platform-native mechanism per target: ELF symlink chain (libfoo.so.MAJOR) on FreeBSD/Linux, dylib symlink chain plus linker -compatibility_version/-current_version flags on macOS

Resolves the open macOS-vs-FreeBSD versioned-naming reconciliation flagged in REQ-versioned-naming-bsd-lib-mk-req. A single pair of macros, SHLIB_MAJOR (and optionally SHLIB_MINOR), is the one place a module author expresses versioning intent, regardless of target platform. mk.lib.mk translates this per platform: on FreeBSD/Linux (ELF), it produces the real file libfoo.so.MAJOR[.MINOR] with the standard libfoo.so -> libfoo.so.MAJOR symlink chain, matching real bsd.lib.mk unchanged. On macOS (Mach-O), it produces the real file libfoo.MAJOR.dylib with a libfoo.dylib -> libfoo.MAJOR.dylib symlink (same symlink-chain shape, macOS-native naming), and additionally feeds SHLIB_MAJOR/SHLIB_MINOR into the linkers native versioning flags (-compatibility_version, -current_version) -- since embedded Mach-O version metadata, not just the filename, is macOS actual ABI-compatibility mechanism. One author-facing macro pair, two platform-appropriate emission strategies.
