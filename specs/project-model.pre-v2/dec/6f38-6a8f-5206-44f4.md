# A dedicated, script-driven (not make-driven) test harness validates the mk.*.mk implementation itself, distinct from end-user test infrastructure (which remains deferred): test cases are packaged as archives, expanded fresh into a temp directory per run, built with bmake, result recorded, temp directory deleted

User specified a test harness for validating rade-bmake's OWN implementation (the mk.*.mk files, macros, target behaviors), NOT end-user test infrastructure for frameworks/modules built WITH rade-bmake -- that remains correctly deferred per REQ-tests-docs-versioning-deferred-req, which is a different concern (does a module declare/build ITS OWN tests) and is not reopened by this decision. Design, confirmed via a working prototype: each test case is a self-contained minimal project (a workspace/framework/module fragment exercising one feature) packaged as a .tar.gz archive, not a live directory in the repo. A driver script (NOT a make target -- deliberately external, so testing the build system doesn't depend circularly on the build system working correctly) does, per archive: mktemp a scratch directory, expand the archive into it, run bmake there with the case's declared arguments, record PASS/FAIL against the case's declared expectation (exit code, and/or a specific output file existing, and/or expected substrings in build output), then delete the expanded scratch directory. Prototyped and confirmed working end to end: 3 real test cases (yacc/lex suffix rules, LIB_SHARED static+shared behavior, dynamic SUBDIR discovery -- all three reusing findings from this sessions empirical validation pass) all pass; a deliberately broken 4th case was confirmed to correctly FAIL with a clear reason and a non-zero overall exit code, without leaving any leftover scratch directories behind, and preserving the build-output log specifically for the failing case for inspection.
