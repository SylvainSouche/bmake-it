# The rade-bmake project itself has a script-driven test harness (not a make target) validating mk.*.mk behavior: test cases packaged as archives, each expanded into a fresh temp directory, built with bmake, result recorded against a declared expectation, temp directory deleted; documented per case

Distinct from and does not reopen REQ-tests-docs-versioning-deferred-req (which covers whether END-USER modules/frameworks built with rade-bmake can declare their own tests -- still deferred). This REQ is about testing rade-bmake's OWN mk.*.mk implementation. Design: test-case fixtures live as .tar.gz archives (not live checked-in directories), each containing a minimal self-contained project plus a small config file declaring: a description (for documentation), the bmake arguments to invoke, and an expectation (exit code, and/or a specific file expected to exist afterward, and/or expected substrings in build output). A driver script external to make itself iterates the archives: expand each into a fresh mktemp scratch directory, run bmake there, check the result against the declared expectation, print PASS/FAIL with a reason, delete the scratch directory (on PASS; a FAIL preserves its build log for inspection), and exit non-zero overall if anything failed. Confirmed working via a real prototype (prototypes/run-tests.sh + prototypes/cases/*.tar.gz) covering three of this sessions empirical findings (yacc/lex suffix rules, LIB_SHARED static+shared behavior, dynamic SUBDIR discovery) plus a deliberate-failure case confirming the FAIL path itself works correctly. Open follow-ups for a fuller implementation: test-case authoring conventions/templates, whether cases can be organized by validation-plan tier (spec/60-bsd-make-validation-plan.md), and CI integration.
