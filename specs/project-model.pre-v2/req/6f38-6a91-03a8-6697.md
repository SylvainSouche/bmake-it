# mk.prog.mk/mk.lib.mk must NOT rely on inherited bsd.dep.mk automatic depend: wiring, which is confirmed non-functional standalone in both tested lineages; instead they must implement a thin, explicit depend: target that invokes the standalone mkdep tool (or equivalent) directly and captures its output -- the underlying per-source-file header-scanning capability itself is confirmed to work correctly

Corrects REQ-mkdep-style-header-dependency-tracking-req in light of OBS-validation-bsd-dep-mk-automatic-wiring-broken: the general per-module .depend REQUIREMENT (touching a header only recompiles the .o files that actually include it) is unchanged and still achievable, but the MECHANISM must be corrected. Rather than relying on real bsd.dep.mk's own depend: target (broken/absent standalone in both FreeBSD and NetBSD lineages as empirically tested), mk.prog.mk/mk.lib.mk must define their own explicit depend: target that invokes the standalone mkdep tool (confirmed working correctly, producing genuine transitive header dependencies) directly against the module's SRCS, writing the result to a generated .depend file that is then .included normally. This is a small, targeted piece of custom logic (a handful of make recipe lines, or an equivalent small external script) -- not a wholesale rewrite of bsd.prog.mk/bsd.lib.mk, whose core compile+link+shared-library-versioning behavior remains confirmed reusable (REQ-shlib-major-minor-cross-platform-emission-req, OBS-validation-yacc-lex-suffix-rules-confirmed). This is a deliberate, evidence-based exception to CON-use-bsdmake's general reuse-first principle, scoped narrowly to the one piece confirmed not to work as assumed, rather than a rejection of that principle overall.
