# The build system does not validate PREREQS ordering or detect cycles; a misordered PREREQS list surfaces only as an ordinary header-not-found compile error, not a dedicated diagnostic

Closes the open follow-up on REQ-framework-prereqs-macro-req regarding what happens when PREREQS is misordered: nothing special, for now. Header lookup follows PREREQS declaration order; if that order is wrong, compilation fails with a normal 'header not found' error, the same as any missing-include failure. No dedicated cycle-detection or order-validation pass is implemented at this stage -- explicitly deferred, may be added later.
