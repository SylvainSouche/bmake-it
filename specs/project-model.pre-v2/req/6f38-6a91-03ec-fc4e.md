# Before linking a module, mk.prog.mk/mk.lib.mk verify each LIBS= entry's build artifact actually exists; a missing one produces an explicit 'dependency not yet built' error naming the specific missing library, rather than an opaque linker failure

Adds a fail-fast guard to the link step of REQ-fused-build-per-module-full-dependency-order-req: immediately before invoking the linker, for each name in LIBS=, check that the corresponding library artifact exists (module-level build/<KEY>/lib/ for a sibling module, or framework-level build/<KEY>/lib/ for a PREREQS-resolved framework library). If any are missing, fail with an explicit error identifying which dependency is missing and why (e.g. 'cannot link hello: prerequisite library greet (from LIBS=) has not been built yet'), rather than proceeding to invoke the linker and surfacing its own generic missing-library error. This should essentially never fire in normal operation, since REQ-order-target-blank-run-req already sequences builds correctly -- its value is as a clear diagnostic when something has genuinely gone wrong (stale cache, manual/partial build, bug), rather than a cryptic '-lgreet: No such file or directory' from the linker itself.
