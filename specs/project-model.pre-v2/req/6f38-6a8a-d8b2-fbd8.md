# Modules and frameworks build via a fused compile+link (and header-generation) cycle, one unit at a time, in an order where a dependency (via LIBS, or via a consumed promoted-generated header) is FULLY completed before its dependent starts building at all

Supersedes REQ-sibling-module-ordering-link-only-req. Build strategy: each module (and each framework) is built as one fused unit -- generate headers if applicable, promote per INCL= (REQ-incl-macro-promotes-generated-headers-req), compile src/ to obj/, link to bin/ or lib/, copy up -- matching real bsd.*.mk idiom rather than separate global compile-all/link-all phases. Build ORDER across modules within a framework, and across frameworks in a workspace (REQ-framework-build-order-follows-prereqs-graph-req), is a topological order over TWO kinds of dependency edges: (1) a modules LIBS= entries (REQ-libs-macro-link-only-headers-via-prereqs-req), and (2) any consumption of another modules/frameworks promoted-generated headers (REQ-generated-headers-in-build-tree-req). Either kind of edge requires the depended-on unit to be FULLY built (not just compiled) before the dependent starts. As with framework-level ordering, no cycle detection is implemented (REQ-prereqs-misorder-no-validation-req) -- an actual cycle has undefined behavior.
