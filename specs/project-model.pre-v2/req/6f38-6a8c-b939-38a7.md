# Debug vs release build variant is controlled via real bsd makes own native flag variables (DEBUG_FLAGS for debug symbols, an optimization-level flags variable for release), not a new unified MODE= switch

No new abstraction is introduced for debug/release selection, unlike TOOLCHAIN= (REQ-toolchain-cli-variable-req), because bsd make already provides this natively: DEBUG_FLAGS (conventionally -g) adds debug symbols, and an optimization-level flags variable (exact name TBD -- COPTFLAGS or CFLAGS-family, needs verification against real bsd.*.mk source) controls optimization. These are set/overridden directly on the make command line or in a module makefile, the same as any ordinary bsd make variable -- no MODE=debug|release wrapper. This is consistent with REQ-variant-out-of-scope-for-dirtree (debug/release never gets its own build/<KEY>/ subdirectory -- switching flags and rebuilding overwrites the existing target output in place). Exact optimization-flags variable name is an open follow-up pending empirical bsd.*.mk verification.
