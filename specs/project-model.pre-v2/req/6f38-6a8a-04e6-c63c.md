# Workspace, framework, and module levels each use a file named literally 'makefile', which .includes a role-specific helper: <mk.workspace.mk>, <mk.framework.mk>, <mk.prog.mk>, or <mk.lib.mk>

Every level in the tree (workspace root, each framework, each module) has exactly one file named 'makefile' (not 'makefile.mk'). Each is a thin declaration file: it sets a handful of role-specific variables (see REQ-workspace-parent-list-macro, REQ-framework-prereqs-macro, REQ-module-build-macros) and then does a bsd-make-style .include of a shared helper file matching its role -- mk.workspace.mk at workspace level, mk.framework.mk at framework level, and either mk.prog.mk (building an executable) or mk.lib.mk (building a library, static or shared) at module level. This mirrors real BSD make's own bsd.prog.mk/bsd.lib.mk convention (CON-use-bsdmake), scoped up to this project's own workspace/framework/module notions. Supersedes REQ-module-makefile-fields (which used the filename 'makefile.mk').
