# PREFIX is a NEW, project-specific variable (not a reuse of any native bsd.prog.mk/bsd.lib.mk mechanism); mk.prog.mk/mk.lib.mk must derive the individual *DIR variables (BINDIR, LIBDIR, etc.) from it themselves, since bare bsd.prog.mk/bsd.lib.mk have no such derivation. DESTDIR remains correctly bsd-make-native, confirmed working as expected

Corrects REQ-destdir-prefix-confirmed-req in light of OBS-validation-destdir-native-prefix-is-not: DESTDIR is confirmed genuinely bsd-make-native and composes correctly with whatever *DIR variables are set (BINDIR, etc.) -- no change needed there. PREFIX, however, is reclassified from 'reused native' to 'new, project-specific' in the macro reference (50-makefile-macros.md): this project's mk.prog.mk/mk.lib.mk must itself derive BINDIR, LIBDIR, and any other *DIR variables from a project-level PREFIX= (e.g. BINDIR?=${PREFIX}/bin, LIBDIR?=${PREFIX}/lib), since real bsd.prog.mk/bsd.lib.mk do not perform this derivation automatically -- they only understand the individual *DIR variables directly. Also found: real bsd.prog.mk's install rule does not auto-create missing parent directories in DESTDIR (install without -d assumes the destination tree already exists) -- our install/packaging mechanism (REQ-packaging-invokes-install-into-distrib-req) needs to explicitly create bin/lib/share subdirectories under DESTDIR before invoking install, or rely on 'install -d'-style directory creation as part of that step.
