# Build outputs live under a build/$OS_ARCH/ directory at module, framework, and workspace levels; obj/ holds per-module intermediate object files, bin/ and lib/ hold final linked artifacts, keyed per target to support cross-compiling multiple targets from the same source tree

At the module level: module/build/$OS_ARCH/obj/ holds intermediate compiled object files (.o) for that module's sources -- pure build-time scratch space, safe to delete/clean independently per target. At the framework level: framework/build/$OS_ARCH/{bin,lib}/ holds the linked artifacts (executables, shared/static libraries) produced by the framework's modules for that target, consolidated so other frameworks/modules can find them at a predictable path without reaching into per-module scratch directories. At the workspace level: workspace/build/$OS_ARCH/{bin,lib}/ similarly consolidates across all frameworks in the workspace. Because every level's build tree is keyed by $OS_ARCH, several different targets can be built from the same checked-out source tree at the same time without clobbering each other. Supersedes REQ-build-obj-os-arch-output (module-only obj/<OS_ARCH>). Open follow-ups: (1) exact aggregation mechanism from module to framework to workspace level (copy vs symlink vs direct build-to-location), (2) whether $OS_ARCH also needs to encode build variant (debug/release) as a separate axis, (3) packaging/distribution format is still undecided and not yet part of this structure.
