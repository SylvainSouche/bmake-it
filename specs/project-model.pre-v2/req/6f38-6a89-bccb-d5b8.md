# A module/framework resource source tree uses share/common/, share/<os>/, and share/<os>_<arch>/ subdirectories, most specific wins, with no toolchain axis

Resolves the open naming and fallback-granularity follow-ups on REQ-resource-file-model. The resource source directory is named share/. Within it, three specificity levels are recognized: share/common/ (files applicable regardless of target), share/<os>/ (files applicable to any architecture of a given OS, e.g. share/freebsd/), and share/<os>_<arch>/ (files applicable only to one specific OS+arch pairing, e.g. share/freebsd_x64/), used only when that level of override is actually needed by the resource in question. When staging resources into build/<KEY>/share/ (or similar, per REQ-resource-file-model) for a given target, the most specific applicable variant wins over less specific ones for files present at multiple levels. Unlike the compiled-artifact target key (OS+arch+toolchain, see REQ-target-key-includes-toolchain), the resource fallback key is OS+arch only -- toolchain does not affect resource variant selection.
