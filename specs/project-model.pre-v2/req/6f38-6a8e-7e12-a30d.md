# Build order for both module-level (LIBS=) and framework-level (PREREQS=) dependency graphs is generated via: query each unit dependency macro in isolation (bmake -f <dir>/makefile -V <MACRO>), topologically sort (Kahn), ignore out-of-scope references, emit a generated SUBDIR= .mk fragment consumed by bsd.subdir.mk

Formalizes the working prototype (gen-mod-order.sh) into the design: implements the previously-undesigned recursion-ordering piece of REQ-fused-build-per-module-full-dependency-order-req and REQ-framework-build-order-follows-prereqs-graph-req. At module level: mk.framework.mk queries each *.m directorys LIBS= via , builds the dependency graph (edges only among locally-discovered modules; references to anything else -- e.g. a PREREQS-resolved framework library -- are silently ignored for this graph, since that dependency is satisfied by REQ-headers-resolved-from-source-req/REQ-aggregation-step-copies-outputs at the framework level, not module-level ordering), topologically sorts it (Kahn algorithm), and writes the result to a generated SUBDIR= .mk fragment consumed via .include before .include <bsd.subdir.mk>. The identical mechanism applies one level up at workspace level, querying each frameworks PREREQS= instead of LIBS=. This generated fragment is the same artifact referred to (at a policy level, without this concrete mechanism) in REQ-prereqs-resolution-cached-like-depend-req -- exact caching/staleness-detection triggers for regenerating it remain deferred per that REQ and OBS-cache-mechanism-needs-empirical-check, but the GENERATION algorithm itself is now confirmed and no longer an open design question. Cycle handling: a genuine cycle causes the generation step to fail loudly with a clear diagnostic (confirmed via prototype), rather than the vaguer "surfaces as a header-not-found error" behavior anticipated by REQ-prereqs-misorder-no-validation-req for framework-level PREREQS misordering -- this is arguably a strict improvement (an explicit cycle error is clearer than an indirect compile failure) and does not contradict that REQ, which only committed to NOT implementing dedicated validation, not to suppressing a natural byproduct of the sort algorithm itself.
