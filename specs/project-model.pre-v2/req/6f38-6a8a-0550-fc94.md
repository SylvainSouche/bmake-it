# Module makefile variables: PROG=name (executable, mk.prog.mk), or LIB=name with optional LIB_SHARED=YES (library, mk.lib.mk); LINK_WITH=lib1 lib2 ... controls both header visibility and link-time linking

Refines REQ-module-makefile-fields and REQ-uniform-makefile-filename-req with concrete macro names. Executable modules: .include <mk.prog.mk> plus PROG=<name>. Library modules: .include <mk.lib.mk> plus LIB=<name>, and LIB_SHARED=YES to produce a shared library (default behavior when LIB_SHARED is unset -- presumably static/archive -- not yet explicitly confirmed, open follow-up). LINK_WITH=<lib1> <lib2> ... is a space-delimited list of other modules/libraries this module depends on, used for BOTH compile-time header access (pulling in their exposed include paths) and link-time linking against them -- a single macro drives both concerns, unlike real mkmk which relied on the separate identity-card/prereq mechanism for header access and LINK_WITH purely for linking.
