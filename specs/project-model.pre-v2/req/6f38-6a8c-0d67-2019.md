# make install fails/refuses if the current (or selected) targets build/<KEY>/ output does not already exist -- it does not implicitly build first; cross-filesystem install is deferred, not designed

Refines REQ-install-target-exists-req and REQ-destdir-prefix-confirmed-req: make install requires the relevant targets build/<KEY>/{bin,lib,share} to already exist and be built -- it is not implicitly dependent on all/the default build target the way some install targets are. Attempting install before building the target is an error/no-op, not an automatic build-then-install. Cross-filesystem install (exact scenario not yet fully specified by the user) is deferred, not designed at this stage -- joins REQ-app-bundle-deferred-req and the other standing later items.
