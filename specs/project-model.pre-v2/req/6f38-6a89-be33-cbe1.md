# The compound target key is formatted as <os>-<arch>-<toolchain>, e.g. macosx-arm64-llvm, freebsd-amd64-gcc; arch uses each platform native architecture name (arm64, amd64) at ISA-baseline granularity, not finer per-CPU-generation variants

Finalizes the string format left open by REQ-target-key-includes-toolchain: <os>-<arch>-<toolchain>, hyphen-separated. Examples for phase 1 (REQ-phase1-concrete-targets): macosx-arm64-llvm, macosx-arm64-gcc, freebsd-amd64-llvm, freebsd-amd64-gcc. Architecture labels use each platform own native name at ISA-baseline granularity (arm64 for Apple Silicon, amd64 -- FreeBSD own name, not x64/x86_64 -- for FreeBSD/Intel), matching what uname -m/-p report so host-target autodetection can use the value directly without a mapping table. Finer per-CPU-generation ISA tuning is out of scope for the directory key -- it is a compile-flag concern only. Exact <os> label spelling (macosx vs macos vs darwin, freebsd vs FreeBSD) still open, minor, low priority.
