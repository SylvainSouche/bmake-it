# A library module declares SHLIB_MAJOR (and optionally SHLIB_MINOR); mk.lib.mk emits libfoo.so.MAJOR[.MINOR] with an ELF symlink chain on FreeBSD/Linux, and libfoo.MAJOR.dylib with a dylib symlink chain PLUS linker -compatibility_version/-current_version flags on macOS

Closes the open follow-up on REQ-versioned-naming-bsd-lib-mk-req. Module makefile macros: SHLIB_MAJOR=<n> (required for a versioned shared library), SHLIB_MINOR=<n> (optional, finer versioning). mk.lib.mk (REQ-uniform-makefile-filename-req) emits per platform: FreeBSD/Linux -- libfoo.so.MAJOR[.MINOR] as the real linked artifact, libfoo.so symlinked to it, identical to real bsd.lib.mk behavior; macOS -- libfoo.MAJOR.dylib as the real linked artifact, libfoo.dylib symlinked to it, and the linker invoked with -compatibility_version MAJOR -current_version MAJOR.MINOR (or similar) so the version is also embedded as native Mach-O metadata, not just expressed via filename. This is the single mechanism used regardless of phase-1 vs. later targets.
