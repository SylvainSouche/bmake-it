# Empirically confirmed: real bsd.prog.mk .y/.l suffix rules work automatically with zero explicit rule declarations, producing per-file-named output (grammar.c/grammar.h, not y.tab.c/y.tab.h), avoiding multi-grammar collisions

Test performed: installed the bmake package (portable NetBSD make) via apt, fetched real FreeBSD share/mk (sparse checkout of freebsd/freebsd-src from GitHub), built a minimal module with SRCS=grammar.y lexer.l main.c and .include <bsd.prog.mk> with zero explicit suffix-rule declarations. Result: yacc and lex ran automatically via built-in suffix transformation rules, compiled and linked cleanly, and the resulting binary ran correctly. Notably, the .y.c rule names output after the source files own basename (grammar.y -> grammar.c + grammar.h), NOT the classic y.tab.c/y.tab.h -- this means multiple yacc files in one module do not collide, which is better than the naive assumption. CONFIRMS Tier 1.4 of the validation plan (spec/60-bsd-make-validation-plan.md) -- REQ-supported-languages and REQ-module-src-auto-discovery need no changes for this. One unresolved wrinkle: the MK_MAN=no / WITHOUT_MAN=yes man-page-suppression knobs did not work as expected in this portable-bmake-plus-fetched-share/mk environment (the man-page sub-target still failed) even though the actual program compiled and linked successfully regardless -- likely an artifact of not running FreeBSDs own native make binary with the full src.opts.mk ecosystem; flagged for re-verification on a real FreeBSD box, not treated as a confirmed finding either way.
