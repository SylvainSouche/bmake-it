# Empirically confirmed: DESTDIR composes correctly and is genuinely bsd-make-native (staging root prepended to BINDIR etc.). But PREFIX is NOT a native bsd.prog.mk/bsd.lib.mk concept at all -- neither file references it; real FreeBSD base-system install uses hardcoded individual *DIR variables (BINDIR, LIBDIR, etc.) directly, with no unifying PREFIX that derives them

Test performed: built and installed a minimal PROG=hello module with BINDIR=/bin set explicitly, via 'make install DESTDIR=/tmp/stage'. Result: DESTDIR correctly prepended to produce /tmp/stage/bin/hello, working exactly as expected -- DESTDIR is confirmed genuinely bsd-make-native. However, grepping all of bsd.own.mk, bsd.prog.mk, and bsd.lib.mk for PREFIX found zero references -- the variable does not exist in this part of the build system at all. Real FreeBSD base-system install relies on hardcoded individual *DIR variables (BINDIR, LIBDIR, INCLUDEDIR, etc., each with their own convention/default) rather than a single PREFIX=/usr/local-style variable that derives all of them, the way GNU autotools or MacPorts (PREFIX=/opt/local, in MacPorts own portfile system, not inherited from bare bsd.prog.mk) do it. This corrects REQ-destdir-prefix-confirmed-req, which had the user confirm PREFIX as bsd-make-native -- that specific claim is factually wrong; DESTDIR is correctly native, PREFIX is not.
