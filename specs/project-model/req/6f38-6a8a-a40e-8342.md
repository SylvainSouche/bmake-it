# Frameworks are built in a topological order derived from the workspace-wide PREREQS dependency graph: a framework only builds after all frameworks named in its PREREQS have completed building; behavior on an actual dependency cycle remains unspecified

Refines REQ-workspace-build-sequence-req: step 2 (resolve PREREQS) does not just establish header search paths, it also determines framework BUILD ORDER for the whole workspace -- a topological order over the dependency graph formed by every frameworks PREREQS declarations. This is required because a dependent framework needs its prereqs build output to already exist: compiled libraries for linking (build/<KEY>/lib/) and any promoted public generated headers (build/<KEY>/include/, REQ-generated-headers-in-build-tree-req) -- hand-written headers impose no such ordering since they are read from source. Consistent with REQ-prereqs-misorder-no-validation-req, no cycle detection is implemented; an actual dependency cycle across frameworks has undefined behavior for now, deferred.
