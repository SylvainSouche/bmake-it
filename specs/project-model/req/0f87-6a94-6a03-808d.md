# Producing win-target output does not require running the build from within Cygwin; it can be cross-compiled from any capable host via a mingw-w64-class toolchain, same as any other cross-compile target; the exact mingw-vs-Cygwin toolchain distinction is deferred, not in scope for phase 1

Supersedes REQ-win-target-via-cross-toolchain-req (unchanged content, re-pointed ancestor only). Refines REQ-windows-hosts-cygwin-wsl and REQ-os-label-set-req-v2: a win target build is not inherently tied to running from a Cygwin host. Like any other target in this system (REQ-target-key-includes-toolchain), it is addressable via a cross-compiling toolchain from any host capable of running one -- concretely, a mingw-w64-class toolchain run from Linux, WSL (itself a linux-family host, not a distinct win-producing host), macOS, or FreeBSD. Separately, Cygwin's own native gcc remains a possible way to build win targets when running directly within a Cygwin environment, producing PE binaries that depend on cygwin1.dll at runtime -- a different runtime-dependency profile than a mingw-produced binary. Deferred, not decided: whether both toolchain flavors are supported, which is default, and how they are named/distinguished in the target key. Not required for phase 1 (REQ-phase1-concrete-targets does not include any win target).
