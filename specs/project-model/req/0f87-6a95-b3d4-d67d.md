# Each cross target's clang triple/sysroot layout must match that platform's real distro/vendor conventions, not a generic guess

Concrete, empirically-verified per-target requirements: (1) freebsd triple is <arch>-unknown-freebsd. (2) linux triple is <arch>-linux-gnu with NO 'unknown' vendor component -- clang's multiarch header search needs the triple to match the distro's exact directory naming (Debian: aarch64-linux-gnu); the sysroot must also include the top-level ld-linux-*.so.1 symlink (lives in /usr/lib on merged-/usr distros like Debian, not physically in /lib despite /lib -> usr/lib), and must be extracted on a case-sensitive filesystem (Linux kernel headers collide on macOS APFS default). (3) macos triple is <arch>-apple-macos<version>, and needs an explicit -Wl,-platform_version,macos,<min>,<sdk> linker flag to work around a driver/linker split-version mismatch seen in some clang/lld distro packages (confirmed on Debian's clang-22/lld-22 against a modern Xcode 26 SDK). Verified end-to-end for all three: genuine FreeBSD ELF, genuine Mach-O arm64 executable, and a genuine Linux ELF that was actually executed on real Linux (not just file(1)-checked). See impl/mk/mk.toolchain.llvm.mk and impl/tests/harness/run-matrix.sh (cross-linux-freebsd, cross-linux-macos, cross-netbsd-linux jobs).
