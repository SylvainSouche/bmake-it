# Cross-compilation also works within the same OS across architectures (e.g. Linux/arm64 host targeting Linux/amd64), not just across OS boundaries

Same mechanism as the cross-OS directions (clang --target/--sysroot), but the amd64 Linux sysroot needed two things the aarch64 one didn't surface: (1) usr/lib/gcc/<multiarch>/<ver> for crtbeginS.o/crtendS.o/-lgcc -- omitted by mistake when only usr/lib/<multiarch> was copied, caught by a link failure, not a silent wrong build; (2) the /lib64/ld-linux-x86-64.so.2 interpreter symlink must be copied as a dereferenced regular file, not a symlink -- its target is an absolute host path (/lib/x86_64-linux-gnu/...) that only resolves inside the sysroot-building container, not under --sysroot as lld sees it. Verified end-to-end: built on an arm64 Linux container, the resulting x86-64 ELF was then actually executed (not just file(1)-checked) via --platform linux/amd64 qemu-user emulation, printing the expected output. See impl/tests/harness/run-matrix.sh (cross-linux-arm64-amd64 job) and impl/mk/mk.toolchain.llvm.mk.
