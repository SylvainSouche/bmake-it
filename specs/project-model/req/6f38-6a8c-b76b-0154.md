# Each module maintains a generated, mkdep-style .depend file tracking which of its source files include which headers (transitively), so make only recompiles the .o files actually affected when a header changes

Extends the fused per-module build (REQ-fused-build-per-module-full-dependency-order-req) with standard bsd make incremental-rebuild machinery: a per-module generated .depend file, produced via a mkdep-style dependency scan of that modules src/ (REQ-module-src-auto-discovery), recording which source files include which headers -- own module-private headers, framework local/include, and PREREQS-resolved headers (REQ-three-level-header-visibility-req, REQ-headers-resolved-from-source-req) alike. This file is .included by the modules build so that touching a header only triggers recompilation of the specific .o files that transitively include it, not the whole module. Distinct from, though mechanically similar to, the workspace/framework-level PARENT_WS/PREREQS resolution cache (REQ-prereqs-resolution-cached-like-depend-req) -- exact regeneration trigger and staleness detection for both caches is deferred pending empirical bsd.*.mk/build.*.mk investigation (OBS-cache-mechanism-needs-empirical-check).
