# Resource files can live at both module and framework level, support per-target variants with fallback, and are staged through the same build/<KEY>/ tree as libraries

User refined the earlier simple module-only resource-file requirement in three ways, after seeing how real mkmk handles this: (1) both modules and frameworks can carry their own resource files, not modules only; (2) resources support per-target variants with a fallback hierarchy, analogous to real mkmk's OS-specific resource directories (see OBS-mkmk-runtime-view-and-resources); (3) resource staging is not a separate mechanism -- it reuses the same build/<KEY>/ tree and copy-upward aggregation already decided for bin/lib (REQ-aggregation-step-copies-outputs), rather than a distinct 'runtime view' step. Supersedes REQ-module-resource-files.
