# Both the toolchain slot and a new ABI/libc slot are omitted from the target key when they hold the default value for that OS; toolchain default is llvm, ABI default is OS-specific (msvc for win)

User confirmed a general omit-if-default convention for the target key, extending it from just ABI/libc to toolchain as well. Confirmed defaults: toolchain default is llvm (matches the already-confirmed REQ-default-toolchain-llvm) -- so macos-arm64-llvm collapses to macos-arm64, while macos-arm64-gcc keeps its explicit gcc suffix since gcc is non-default. ABI/libc default is OS-specific and only applies where an ABI/libc axis exists at all (win: msvc; freebsd/macos: no ABI axis, not applicable; linux: default libc still an open follow-up question, see REQ-linux-libc-default-open). The general key shape becomes <os>-<arch>[-<toolchain-suffix-if-non-default>][-<abi-suffix-if-non-default-and-applicable>], with each optional suffix appended only when its value differs from that OSs default. Supersedes the earlier target-key examples in REQ-target-key-string-format-req and REQ-phase1-concrete-targets, which always showed the toolchain explicitly.
