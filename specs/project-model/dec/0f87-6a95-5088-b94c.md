# LIB=' default value additionally strips a leading 'lib' prefix from the module directory name, to avoid a redundant liblibfoo.so output filename

Discovered when reviewing the impl/rade-bmake implementation: mk.lib.mk defaults LIB= for a directory like libgreet.m to 'greet' (stripping both '.m' and a leading 'lib'), whereas prog-lib-default-to-module-name-req-v2 as recorded only calls for stripping '.m'. The user confirmed this stripping should be part of the spec: real bsd.lib.mk/mk.lib.mk conventions prepend 'lib' to LIB= when naming shared/static output (lib${LIB}.so, lib${LIB}.a), so a library module directory already conventionally named lib<name>.m would otherwise default to LIB=lib<name>, producing a redundant liblib<name>.so. Stripping the leading 'lib' before defaulting avoids that and matches ordinary Unix library naming (-l<name> / lib<name>.so).
