# LINK_WITH is renamed LIBS (dev + system libraries to link with); it is link-time ONLY. Header lookup no longer uses it at all -- headers are found solely via the framework's PREREQS

User reversed the earlier dual-purpose design (REQ-module-build-macros-req, which had LINK_WITH drive both header visibility and linking): the macro is renamed LIBS, and covers both 'dev' libraries (this project's own prereq/sibling libraries) and system libraries (e.g. -lm, -lpthread), but is used PURELY at link time. Header include-path resolution is driven exclusively by the framework's PREREQS declaration (REQ-framework-prereqs-macro-req) -- LIBS/LINK_WITH plays no role in it at all. This is a genuine reversal of the earlier design, not just a rename, so REQ-module-build-macros-req is superseded rather than merely refined.
