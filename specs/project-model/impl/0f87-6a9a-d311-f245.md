# mk.vcvarsall.mk (included from mk.toolchain.msvc.mk only when cl.exe isn't already on PATH): replicates vcvarsall.bat's environment discovery in pure bmake -- locates the VS install via vswhere.exe, reads the default MSVC toolset version from Microsoft.VCToolsVersion.default.txt, finds the highest-versioned installed Windows SDK, and constructs the PATH/INCLUDE/LIB triple itself; CC/CXX/AR in mk.toolchain.msvc.mk then prefix the wrapper scripts with 'env PATH=... INCLUDE=... LIB=...' so every invocation carries the right environment without needing a Developer Command Prompt or a manual vcvarsall.bat call first. A real bug found and fixed during verification: bmake's own exists()/file-read builtins need the Cygwin/POSIX form of a path (backslash Windows paths are taken as literal filename characters, not separators)
