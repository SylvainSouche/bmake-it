# Contract for characters in workspace, framework, module and install-directory names: supported set, no silent success, readable refusal for the rest

PROPOSED, not decided. (1) Supported on every platform: letters, digits and . _ - + @ % ~ ^ [ ] and non-ASCII letters, in every name and in the mk directory. (2) No silent success: a build that built nothing never reports success. (3) Every other character is refused before any build step with a message naming the character, the path and the rule (graceful-error-on-missing-variable-req), for a workspace, framework or module name, a directory above them, and the mk directory (which tolerates more: # ! : , = * ? { } work there, so its refused set is smaller). Open: whether to also quote the recipe expansions (about 320, bmake :Q) so that space and the shell characters work, which matters on Windows and macOS paths with spaces; where the check lives (mk.common.mk for .CURDIR, the order scripts for discovered names); the Windows set (the file system refuses " * ? < > | : and backslash). Case 116 checks 1 and 2 now and ends SKIP on the known gaps (star question equals).
