# Corrects OBS-validation-bsd-dep-mk-automatic-wiring-broken, which tested the wrong mechanism. Real bsd.sys.mk/bsd.dep.mk wire the COMPILER's own -MD flag to generate a per-object .depend.<obj> file automatically on every ordinary compile -- no separate make depend step, no mkdep tool invocation needed at all. Confirmed fully working end to end: touching a shared header correctly triggered recompilation of exactly the right .o files

The earlier test (OBS-validation-bsd-dep-mk-automatic-wiring-broken) ran `bmake depend` (a separate, explicitly-named target) and inspected only the aggregate .depend file, which was nearly empty, concluding dependency tracking was broken. That conclusion was based on testing the wrong mechanism. Re-examining actual compile output revealed every cc invocation already includes -MD -MF.depend.<objname> -MT<objname> -- this is bsd.sys.mk wiring the COMPILER's own native dependency-generation flag directly into every ordinary compilation, producing a complete, correct, per-object dependency file (.depend.main.pieo, .depend.greet.pieo, etc.) with no separate make depend step and no mkdep tool invocation required at all. Confirmed end to end: touching greet.h and rebuilding correctly triggered recompilation of BOTH main.pieo (transitive include) and greet.pieo (direct include), then relinked -- exactly the incremental-rebuild behavior REQ-mkdep-style-header-dependency-tracking-req originally wanted. This mechanism is separate from, and more relevant than, the `depend:` target and the standalone mkdep tool investigated in the superseded finding -- those still exist and the mkdep TOOL still works standalone as previously found, but neither is what actually provides working incremental dependency tracking by default; the compiler's own -MD flag does, and it needs no custom wiring at all.
