# What bmake itself cannot carry: a dependency source with a space or parenthesis, a hash in a .for item, a -m path with a space, adjacent spaces through modifiers

Measured (macOS bmake 20260406; FreeBSD 15.1 and NetBSD 10.2 make behave the same on the features used): (1) a dependency-line source cannot hold a space (quotes and backslash are read as part of the word, a ? glob does not expand in a directory component) nor a parenthesis (d(1)/x.h is member 1 of archive d); an ampersand, an apostrophe and a hash written \# are fine. (2) .for loop items: a # in an item cuts the substituted line at the # (Unclosed expression). (3) -m <dir with space> is written unquoted into MAKEFLAGS and the sub-make reads two words; MAKESYSPATH carries it, but a colon in a directory name cannot be in MAKESYSPATH, so -m is the way for that. (4) A modifier works on each word of a value, so ${.CURDIR:T} of a path with a space is the last piece of each word; :tW makes it one word. (5) Every modifier after a space is in a value splits it again and joins with ONE space, so two adjacent spaces collapse unless the space is restored last, as one word. (6) bmake -V NAME prints the value unexpanded; -V '${NAME}' expands. (7) A backslash-escaped space survives .for and :S/\\//g undoes it; :Q escapes ! & ( ) * ; < > ? [ ] ^ { | } ~ ' space and #. (8) FreeBSD's make reads % in a target as a pattern (already known).
