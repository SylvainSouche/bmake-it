# Real mkmk's per-module build file uses named macros: object type, program/library name, link libraries, included sub-modules, per-language extra flags, per-language optimization, and a build-disable switch

Key macros seen in the reference docs: one macro selects the produced artifact type (executable, shared library, static archive, an explicitly-loaded-at-runtime shared library, or a Java module); a name macro overrides the default output name; a mandatory link-libraries macro lists what to link against (restricted to the subset available via declared prerequisite frameworks); an aggregation macro lets small sub-modules be folded into a bigger one; per-language extra compile-flag macros and an extra link-flag macro; per-language optimization-level macros; and a per-module 'skip build' switch. This extends REQ-module-makefile-fields with concrete detail. Mostly reinforcing, not conflicting -- worth deciding which of these macros/features we actually want in v1 vs. defer.
