# Delay loading on this host: mingw-w64 with clang+lld (-Wl,--delayload=<dll>, from the normal import library) and with gcc+GNU ld (a delay-import library from the DLL's .def, <triple>-dlltool -y) both start without the DLL and load it at the first call; the helper comes from mingw-w64's libmingwex. Without a failure hook, a missing DLL kills the program at the first call with exit code 127 and no message; a hook (__pfnDliFailureHook2, non-const in mingw-w64's delayimp.h, const in MSVC's) can print the DLL and function and exit -- verified with both linkers. Cygwin output is not reliable: gcc + dlltool -y + libdloadhelper ends with exit status 0 and no output at the failing call; clang+lld --delayload does not delay at all (the program does not start without the DLL). MSVC not tried: the EWDK image was on the failed drive.
