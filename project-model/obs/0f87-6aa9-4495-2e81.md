# MacPorts atf-c++ 0.21 headers use std::auto_ptr, which libc++ removes under C++17 mode (clang's default since ~16); libstdc++/gcc keeps it deprecated-but-present at the same standard level -- a real, host-specific toolchain-packaging gap, not a Bmake It bug

Fixed with -D_LIBCPP_ENABLE_CXX17_REMOVED_AUTO_PTR added unconditionally to _ATF_CXX_CFLAGS in mk.test.mk -- a libc++-recognized back-compat macro (confirmed empirically: compiles clean save for one deprecation warning), no-op and harmless under libstdc++ since gcc's headers don't look at that macro name. Same category as the sanitizer toolchain gaps already documented -- an accommodation, not something requiring a model REQ change.
