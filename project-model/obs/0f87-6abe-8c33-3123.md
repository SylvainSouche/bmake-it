# Round 4 lasviewer migration report: fix 8's LDFLAGS dedup regresses local.mk hook flags and splits two-word flags; a build with nothing to do still re-visits every imported module 4x and rewrites .linkdeps 21x; a clean build double-archives a static lib

User's own words, verbatim (bmake-it-issues-2026-10-01.md, acceptance
project /Users/Shared/programming/pdalviewer/lasviewer, branch
height-models, commit e4b9516, against bmake-it main 173f44a, host
macOS arm64/MacPorts GDAL 3.13.3/GLFW 3.4/glm 1.0.3/clang 22):

Round 3 verdict: Fixes 1-7, 9 and 10 work on lasviewer. Four workarounds
are removed (GDAL prefix hook, ImGui include hook, glm hooks, the 49
GDAL header names), and DOCS=no is in use. A clean build passes, 44
tests pass, and the render is byte-identical to the reference. Fix 8
introduced a regression (item 1).

1. BUG (regression from fix 8): link flags from local*.mk hooks are
dropped, and two-word flags are split. _LDFLAGS_DEDUP != ... at
mk.prog.mk line 256 is evaluated when the file is read; the post-hooks
are read later, by .include mk.local.mk at line 299 (local.mk,
local.<os>.mk); the link rule uses _LDFLAGS_DEDUP, so anything a
post-hook adds to LDFLAGS never reaches the link. Symptom (lasviewer):
Viewer/lasviewer.m/mk/local.macos.mk holds LDFLAGS += -framework OpenGL
-framework Cocoa -framework IOKit, and the link fails with undefined
GL symbols -- no -framework is on the link line. On Linux,
local.linux.mk's -lGL would be lost the same way. Second defect, same
loop: it compares single words, so a flag that takes an argument loses
its repeated keyword -- "-lfoo -framework OpenGL Cocoa -lfoo -Xlinker
-x -Xlinker -dead_strip" style input becomes "-lfoo -framework OpenGL
Cocoa -Xlinker -x -dead_strip", losing the second -framework and
splitting -Xlinker/-dead_strip. Affects -framework X, -Xlinker X,
-weak_framework X, -rpath X, -L X (space form), -include X. Expected:
the removal sees the final LDFLAGS (computed in the recipe, or with =
instead of != after every hook); it treats a flag plus its argument as
one unit; or it removes repeats only among -l*, -L* and -Wl,-rpath,*,
which are what .linkdeps expansion repeats, and leaves everything else
untouched. lasviewer's workaround (remove as the acceptance test):
Viewer/lasviewer.m/mk/pre.macos.mk uses LDFLAGS += -Wl,-framework,OpenGL
-Wl,-framework,Cocoa -Wl,-framework,IOKit (pre-hooks run before line
256, and -Wl, forms are one word), pre.linux.mk uses -lGL.

2. A build with nothing to do still costs about 21s. Fix 3 works:
nothing is re-extracted, recompiled, re-archived or relinked, and
staged headers aren't re-copied (mtimes unchanged). What still happens
on a second bmake with no change: every imported module's import and
staging steps run 4 times (===> imported gdal... x4, ===> staged
header(s) gdal*.h x4, same for glfw/glm/lazperf/copc-lib/ImGui
headers); the 7 .linkdeps files are rewritten, in 3 copies each
(module/framework/workspace), 21 files in all. Harmless today (binary
isn't relinked) but costs time, and a rewritten .linkdeps is one
dependency edge away from spurious relinks. Expected: each module
visited once per build, or its second visit (copy-up) does nothing
when outputs are current, and .linkdeps written only if content
changes.

3. A clean build archives a static library twice. From an empty tree,
one warning remains: "warning: copy-up collision: 'libgeo.a' differs
between source and destination -- overwriting" -- libgeo.a is
archived, copied up, then archived again: a timestamp inside the
archive differs, so the copy differs. Probably the same double visit
as item 2.

4. Known gap, as stated in round 3: REQUIRES=header:<path>. glm is now
imported with IMPORT_LIB=none (which works, and fails clearly if glm/
isn't found), so lasviewer doesn't need it. Low priority.

Worked (round 3), for the record: fixes 1,2,5,6,4,7,9,10 all confirmed
working; fix 8 (duplicate -l dedup) works apart from the regression in
item 1; fix 3 (no-op relink) -- after touching one Geo source, 1
compile then a relink (22s).
