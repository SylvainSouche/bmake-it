# bmake has no notion of compiler-flag/toolchain identity -- changing SANITIZE=/CC=/TOOLCHAIN= etc. between runs does not invalidate already-built .o files, silently producing a binary built with the WRONG flags

bmake's staleness model is purely file-timestamp-based (source newer than object -> rebuild); it has no concept of 'this object was compiled with different flags than requested this time.' bmake SANITIZE=address after a plain bmake leaves every .o from the plain build untouched (source files didn't change), so the final binary silently links stale, non-instrumented objects even though SANITIZE=address was requested -- the sanitizer runtime gets linked in (via LDFLAGS) but the code it's supposed to be instrumenting was never recompiled with -fsanitize=, defeating the whole point without any error or warning.
