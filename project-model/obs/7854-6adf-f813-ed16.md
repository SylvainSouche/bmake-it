# Provisioning the amd64 guests on the Windows host (2026-10-27) broke on things outside the harness: BIOS boot loaders (FreeBSD, NetBSD) print the kernel to VGA and drop serial input that arrives faster than they poll, so the console scripts had to switch the console and type slowly; and every layer build downloads its packages live (pkg.FreeBSD.org, cdn.NetBSD.org, Debian mirrors) through QEMU's DNS relay, which this host's dead fec0:: resolvers make slow -- SRV lookups timed out, a pkgsrc download dropped. The provisioned layer caches installed packages, but the downloads were never cached, so any new host or vm.sh rebuild goes online and installs whatever the mirrors serve that day
