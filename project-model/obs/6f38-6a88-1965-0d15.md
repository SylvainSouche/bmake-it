# Real mkmk also supports Java (with client/server/common module segregation) and Windows-specific mechanisms (DLL export/import macro pattern, COM type-library import); these appear out of scope given the project's C/C++ and macOS/Linux/BSD-only stated scope

Java support includes a module TYPE classification (client/server/common) with restricted cross-type linking and separate generated runtime views. Windows support includes a required per-module dllexport/dllimport macro pattern for shared libraries and a mechanism for importing COM type libraries into C++ sources. Given CON-cross-platform-targets currently lists only macOS/Linux/*BSD as build hosts, and the opening description only mentioned C/C++/ Fortran/JAVA/Express languages in the abstract, these Windows- and Java-specific mechanisms are flagged as likely out of scope rather than assumed in or out.
