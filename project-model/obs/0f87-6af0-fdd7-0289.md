# Tools Bmake It runs that cannot carry a space, an apostrophe or a hash in a path: pkg-config, CMake's makefiles, kyua's results lookup, atf-sh, LLVM ar

Measured on macOS (MacPorts pkg-config, CMake, Kyua, ATF 0.23) and FreeBSD 15.1: (1) pkg-config prints -I/a b/include unquoted and cannot read it back ("Text ended before matching quote"); a # in a .pc value is a comment; so IMPORT=pkg: of a package under such a prefix fails whatever Bmake It does, while <NAME>_PREFIX= does not use it. (2) CMake Unix Makefiles cannot have a # in the build path (make reads it as a comment). (3) kyua report-junit cannot find the results file it just wrote for a test directory with such characters, unless it is given the file (-r). (4) ATF atf-sh libatf-sh.subr tests its directory unquoted: a space stops every shell-script test ("too many arguments"). (5) LLVM ar writes through a temporary file named by replacing every % of the path with a random digit: a % in an absolute archive path stops it (FreeBSD).
