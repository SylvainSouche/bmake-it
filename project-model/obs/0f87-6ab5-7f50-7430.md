# mk.prog.mk and mk.lib.mk always link with ${CC}, never ${CXX} -- a C++ program or shared library fails to link

mk.prog.mk:171 (${_BINOUT}: ${OBJS} recipe) and mk.lib.mk:221 (${_LIBOUT_DIR}/${SHLIB_NAME}: ${OBJS} recipe) both invoke ${CC} unconditionally for the final link step, regardless of whether SRCS contains C++ sources. A C++ module then fails to link with undefined symbols (___gxx_personality_v0, ___cxa_throw, etc.) since ${CC} does not pull in libstdc++/libc++ or the C++ runtime support objects. The example workspace never caught this because examples/myworkspace is C-only. mk.test.mk already links ATF C++ tests with ${CXX} (mk.test.mk:101), so the gap is specific to mk.prog.mk/mk.lib.mk's own final-link recipes, not a project-wide blind spot.
