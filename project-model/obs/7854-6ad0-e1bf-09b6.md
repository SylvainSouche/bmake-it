# On win the target key leaves the ABI slot out only for msvc (target-key-omit-defaults), but mk.common.mk adds an ABI suffix only when the user passes ABI= -- nothing derives it from the toolchain actually used. So Cygwin-native clang output (linked against cygwin1.dll, POSIX) is labelled win-amd64, Cygwin gcc win-amd64-gcc, and mingw-w64 cross output win-amd64: every one claims MSVC's ABI. test-cygwin-gcc-hello-win-amd64 (2026-09-04) recorded win-amd64-gcc as correct.
