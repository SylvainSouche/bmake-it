# Building OpenRider on Cygwin, every nested -V order query (gen-mod-order.sh LIBS/LIB/PROG, gen-fw-order.sh PREREQS) failed with 'no system rules (sys.mk)': Cygwin's bmake keeps sys.mk in /usr/share/bmake/mk, which neither the scripts' search list nor the MAKESYSPATH that mk.workspace.mk/mk.framework.mk force (overriding the user's own, correct one) contains. The errors were discarded (2>/dev/null, || true) and the generators silently fell back to alphabetical order, so frameworks and modules were built before their prerequisites and the build died later with misleading 'not built yet' / header-not-found errors. Same class as mod-order-sysroot-hardcoded-macports-fallback, recurring because the silent fallback was left in place.
