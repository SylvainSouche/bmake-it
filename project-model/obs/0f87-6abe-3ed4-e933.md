# Continued lasviewer migration (bmake-it-issues-2026-09-30.md) found ten more real issues: imported-link-list missing -L for shared imports (gdal/lz4); a fetched module's own tree root not on its include path (ImGui backends/); builds with nothing to do aren't no-ops (a .PHONY fetch prerequisite forcing every rebuild); transitive -l without -L in .linkdeps; header-only imports unsupported (glm); IMPORT_HEADERS= can't glob (GDAL's ~150 loose headers); a program-only framework's own empty lib dir produces an ld search-path warning; duplicate -l entries produce an ld warning; bmake docs writes its landing page into the project's own hand-written docs/, gives an empty page for a framework with no public headers, and has no per-framework opt-out; README still documents the retired bmake test-all

User's own words, verbatim (`bmake-it-issues-2026-09-30.md`, acceptance
project `/Users/Shared/programming/pdalviewer/lasviewer`, branch
`height-models`, host macOS arm64/MacPorts, GDAL 3.13.3/GLFW 3.4/clang 22):

> ## Still worked around in lasviewer (remove the workaround as the acceptance test)
> 1. **Imported link list** (`IMPORT=pkg:gdal`): the recorded list is
>    `pkg-config --libs --static` without the `-L` of the library's own
>    directory. The link then fails with `ld: library 'lz4' not found`.
>    - Workaround: `GIS/libgdal.m/mk/pre.macos.mk` sets
>      `IMPORT_PREFIX=/opt/local`, hard-coded for MacPorts (Homebrew and
>      pkgsrc users must edit it).
>    - Proposal (unchanged): keep the `-L` entries; for a shared import,
>      record only `-l<LIB>` (the dylib carries its own dependencies);
>      use the `--static` list only for a static-only import.
> 2. **Fetched tree root not on the include path** when compiling its
>    own `SRCS=`: ImGui's `backends/*.cpp` include `"imgui.h"` from the
>    root.
>    - Workaround: `GUI/libimgui.m/mk/local.mk`:
>      `CXXFLAGS += -I${.CURDIR}/work/_resolved`.
>    - Without it a fresh tree fails. It only builds if an earlier build
>      already staged `imgui.h`, which hides the bug in incremental builds.
>
> ## Not worked around
> 3. **Builds with nothing to do aren't no-ops**: `libimgui.a` and
>    `libgeo.a` are re-archived, headers are re-staged, and
>    `copy-up collision … differs` warnings appear. Touching one `Geo`
>    source costs about 45 s.
> 4. **Transitive `-l` without `-L`**: a static library's `.linkdeps`
>    reach consumers without the directory of the libraries they name.
>    Harmless in lasviewer only because Viewer lists `GIS`.
> 5. **Header-only imports**: glm has no `.pc` file. Without lasviewer's
>    hook, the step-4 prefix probe found `/opt/local/lib/libglm.dylib`,
>    but only because MacPorts' glm 1.0.3 ships an optional compiled
>    library; a header-only glm such as Debian's would not be found.
>    `IMPORT=pkg:glm` works only through the `IMPORT_CFLAGS` hook, and
>    `REQUIRES=glm` can't express it.
>    - Proposal: an explicit header-only form, e.g. `IMPORT_LIB=none`,
>      plus a header-path check usable by `REQUIRES=` (e.g.
>      `REQUIRES=header:glm/glm.hpp`).
> 6. **`IMPORT_HEADERS` globs**: GDAL installs about 150 loose headers;
>    lasviewer lists the 49 it reaches, by hand.
> 7. **`ld: warning: search path '<fw>/build/<KEY>/lib' not found`** for
>    a framework that only builds a program (Viewer).
> 8. **`ignoring duplicate libraries: -lcopc-lib -lglfw -llazperf`** on
>    the program link: `.linkdeps` expansion repeats entries.
>
> ## New, from trying unused features
> 9. **`bmake docs`**:
>    - The workspace landing page is written to `<ws>/docs/index.html`,
>      inside the project's own hand-written `docs/` directory.
>    - A framework with no public `include/` (Viewer: `local/include`
>      only) gives an empty page and Doxygen warnings
>      (`INPUT … does not exist`, `No files to be processed`).
>    - Imported-library frameworks (GIS, GUI) get docs of nothing useful.
>    - Proposal: skip frameworks with no public headers; write the
>      landing page under `build/` or a configurable directory; perhaps
>      a framework opt-out (`DOCS=no`).
> 10. **README still documents `bmake test-all`**, which was retired in
>     favour of `bmake test REPORT=yes` (mk.test.mk says so, README
>     "Quick start" doesn't).
>
