# Cygwin's clang with --target=x86_64-w64-mingw32 searches Cygwin's /usr/include after the mingw-w64 headers: a POSIX header mingw-w64 lacks (sys/wait.h, sys/resource.h) is silently taken from Cygwin, the wrong runtime, and fails later or deeper ("unknown type name 'id_t'" in /usr/include/sys/resource.h); any ABI=mingw build on a Cygwin host can pick a Cygwin header this way

clang -v: #include <...> search: /usr/lib/clang/22/include, /usr/x86_64-w64-mingw32/sys-root/mingw/include, /usr/include. To fix in mk.toolchain.llvm.mk for ABI=mingw on Cygwin (e.g. -nostdlibinc plus -isystem for clang's and mingw-w64's include dirs), so a missing header is reported as missing.
