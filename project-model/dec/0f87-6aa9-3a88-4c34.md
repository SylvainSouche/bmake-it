# macOS third-party package-manager toolchains are tiered: MacPorts, Homebrew, and pkgsrc/pkgin are tier 1 (fully supported, searched first); Nix is tier 2 (still searched, lower priority) -- Apple's own /usr/bin stays last regardless of tier, per toolchain-detection-prefix-list-authoritative-req

Rationale per package manager, each earning tier 1 for a different reason:
- **pkgsrc/pkgin**: the obvious tier-1 pick -- direct link to the BSD environment (matches this project's own bsd-make heritage), and Bmake It already depends on pkgsrc for NetBSD, so this is consistency with an existing dependency, not a new one.
- **Homebrew**: the macOS package manager with the most user traction/adoption generally -- a pragmatic "meet users where they are" pick, independent of any technical tie to the project.
- **MacPorts**: where Bmake It itself came from -- the project's own original/native toolchain, kept tier 1 on that basis even though it doesn't have Homebrew's broader adoption.

Nix didn't earn tier 1 by any of these three reasons -- no BSD-ecosystem tie, not the dominant macOS choice, not the project's origin -- hence tier 2: still supported, lower priority.
