# Compile-relevant inputs (CC/CXX/CFLAGS/CXXFLAGS/LDFLAGS/SANITIZE/TOOLCHAIN, plus an INPUTS_HASH_EXTRA= extension point) are fingerprinted via cksum into a per-module stamp file every object depends on; the stamp file's own recipe is .PHONY-checked every run but only rewritten (bumping its mtime) when the fingerprint actually changed

Mechanism: a .PHONY _check_inputs_hash: target (always runs, since phony targets are never considered up to date by file existence) computes the current fingerprint via `cksum` (POSIX-standard, present on every phase-1 target uniformly -- deliberately not md5/md5sum, whose binary NAME differs across macOS/Linux/BSD) and compares it against ${BUILD_ROOT}/.inputs-hash's stored content; it rewrites that file ONLY when the fingerprint differs (write-if-different, the standard bmake/make stamp-file idiom -- an unconditional rewrite every build would bump the file's mtime every time and defeat incremental compilation entirely). Every compiled .o target gets ${BUILD_ROOT}/.inputs-hash added as an extra prerequisite, and _check_inputs_hash is wired as a prerequisite of _create_dirs (which already runs before any compile), so by the time bmake evaluates whether a .o is stale, the stamp file's mtime already reflects whether the inputs actually changed this run.

Generic per the brief's own requirement ("must be generic enough for item 5 to reuse"): the fingerprinted string is built from a fixed base set (CC/CXX/CFLAGS/CXXFLAGS/LDFLAGS/SANITIZE/TOOLCHAIN) plus INPUTS_HASH_EXTRA= (empty by default) -- any future mechanism (e.g. item 5's IMPORT= resolution) that needs "rebuild when this input changes" appends its own value to INPUTS_HASH_EXTRA= rather than inventing a second stamp-file mechanism.

Lives in mk.common.mk (shared by mk.prog.mk and mk.lib.mk, and available to any future role file that .includes it).
