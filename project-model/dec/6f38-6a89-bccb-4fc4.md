# Resource source directory is named share/, with a three-level specificity fallback: share/common, share/<os>, share/<os>_<arch>

User named the resource source directory share/ (at module and/or framework level, per REQ-resource-file-model) and specified a three-level fallback hierarchy, from least to most specific: share/common/ (OS- and arch-agnostic data), share/<os>/ (applies to all architectures of a given OS, e.g. share/freebsd/), and share/<os>_<arch>/ (applies only to one specific OS+arch pairing, e.g. share/freebsd_x64/), used only if that narrower variant is actually needed. Notably toolchain is NOT part of the resource fallback key -- unlike the build/<KEY>/ directory key for compiled artifacts (REQ-target-key-includes-toolchain), which does include toolchain. This makes sense since resources are typically toolchain-independent data, not compiled binaries.
