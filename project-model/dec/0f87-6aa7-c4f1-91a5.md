# When the test harness is itself running inside a VM (per harness-native-builds-also-in-vms-req), it must not launch another VM from within that VM -- it can only cross-test back against the original host environment, never spawn nested/sibling VMs

Parallel concern to nested-invocation-reentrancy-guard-req (which guards against nested make invocations self-reentering) -- this guards against nested virtualization instead, a real risk once harness-native-builds-also-in-vms-req puts harness code inside a VM that could otherwise try to provision further VMs of its own.
