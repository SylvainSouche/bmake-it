# Windows shared-library versioning is uniform across all three Windows ABIs (MSVC, Cygwin, MinGW): no filename-embedded version number, no Cygwin cyg-prefix special case -- SHLIB_MAJOR/SHLIB_MINOR translate to an embedded VERSIONINFO resource instead

Two-step decision. First: how should SHLIB_MAJOR/SHLIB_MINOR translate for Windows DLL output? Answer: full native versioning -- embed a VERSIONINFO resource via the resource compiler, matching how real Windows DLLs are versioned (plain filename, no version suffix, unlike the ELF/dylib symlink-chain approach used on FreeBSD/Linux/macOS). Second, a gap this immediately raised: Cygwin has its own native naming convention for shared libraries -- a cyg prefix plus a filename-embedded version number (e.g. cygwin1.dll, cyggreet-1.dll) -- different from both plain Windows/MSVC naming and from the VERSIONINFO approach just decided. Asked explicitly whether the Cygwin-ABI target should follow Cygwin's own convention or stay uniform with the rest of Windows. Decided: keep it uniform -- same plain-filename + VERSIONINFO-resource approach across all Windows ABIs (msvc, cygwin, mingw), no cyg-prefix special case, even though Cygwin-ecosystem users might expect the cyg-prefixed form.
