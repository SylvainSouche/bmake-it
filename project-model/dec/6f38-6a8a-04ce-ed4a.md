# Every level (workspace, framework, module) uses a file literally named 'makefile' (not makefile.mk), which .includes a role-specific bsd.*.mk-style helper file

User chose 'makefile' as the literal filename at every level -- workspace, framework, and module alike -- rather than 'makefile.mk'. Rationale given directly: since the project uses bsd make (CON-use-bsdmake), 'makefile' is the natural/idiomatic choice (bsd make looks for 'makefile'/'Makefile' by default). Each level's makefile is a thin file that sets a handful of variables and then .includes a shared, role-specific helper: workspace makefile does `.include <mk.workspace.mk>`, framework makefile does `.include <mk.framework.mk>`, and a module makefile does either `.include <mk.prog.mk>` (executable) or `.include <mk.lib.mk>` (library) depending on what it builds. This is exactly the bsd.*.mk pattern from CON-use-bsdmake, applied to workspace/framework/module roles instead of bsd make's own prog/lib roles. Supersedes the 'makefile.mk' filename in REQ-module-makefile-fields and resolves the framework-build-file-name and workspace-parent-search-file open questions from the directory-layout spec draft.
