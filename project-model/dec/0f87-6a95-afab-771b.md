# Stop hardcoding /opt/local/share/mk as the BMK_SYS_MK default in mk.framework.mk; let gen-mod-order.sh's own multi-path search run instead

Changed ${BMK_SYS_MK:U/opt/local/share/mk} to ${BMK_SYS_MK:U} (empty default) in mk.framework.mk. gen-mod-order.sh's _bmake_q already searches /opt/local/share/mk, /usr/share/mk, /usr/local/share/mk and uses whichever exists -- that logic was simply never reachable before, since a non-empty value (even a wrong one) short-circuits it. No other file passes a hardcoded BMK_SYS_MK default (mk.workspace.mk's fw-order path never did), so this was a single-file, single-line defect, not a systemic pattern.
