# Establish -Wall -Wextra as the default compile-warning baseline (correcting the gap the brief's own premise assumed didn't exist), and add WARN=none to suppress it (real -w, a master switch overriding -Wall/-Wextra regardless of flag order -- verified) for a module compiling vendored third-party source

Naming diverges from the brief's own suggested CXXWARN=none: a single WARN= applies uniformly to CFLAGS and CXXFLAGS, since a vendored module rarely mixes "some sources need warnings off, some need them on" within the same module, and the brief's own item 7 title ("Vendored third-party source") is language-generic, not C++-specific -- the CXXWARN= example was likely just because the acceptance target's own vendored code (Dear ImGui, item 8) happens to be C++.

-w verified as a genuine master switch: `clang -Wall -Wextra -w ...` and `clang -w -Wall -Wextra ...` both fully suppress a real warning (a deliberately unused variable), regardless of which comes last -- so CFLAGS/CXXFLAGS assembly order does not need to specially sequence WARN=none's -w after the new -Wall -Wextra baseline.

Only affects a module's OWN compiles -- see warn-none-consumer-isystem-dec (D3) for the separate question of whether a vendored module's own PUBLIC headers should suppress warnings for its consumers too.
