# Prerequisite access is search-path-only across declared parent workspaces (dynamic); no physical-copy mode, no mkCopyPreq/mkGetPreq-equivalent commands

Real mkmk offers two prerequisite-access modes: a dynamic search path across workspaces (mkGetPreq) and a physical local copy of prerequisite framework data (mkCopyPreq), each with its own dedicated command to set up. User confirmed this project only wants the dynamic mode: the build looks up missing elements by walking the ordered list of parent workspaces already declared by the workspace itself (REQ-workspace-parent-search-order) -- there is no static/copy mode, and no separate command needed to establish or query the search path (it's simply part of the workspace's own declared configuration, not a runtime/dynamic mkGetPreq-style step). This resolves the long-open static-vs-dynamic prereq access question.
