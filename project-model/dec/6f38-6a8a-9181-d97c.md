# Versioned shared-library naming follows real BSD make's bsd.lib.mk convention (SHLIB_MAJOR / SHLIB_MINOR-style macros producing libfoo.so.X.Y), rather than inventing a new scheme

User resolved the open versioned-naming-mechanism question (REQ-versioned-output-naming-req) by pointing to FreeBSD's own bsd.lib.mk manual page as the model to follow: shared library versioning is controlled via macros like SHLIB_MAJOR (and optionally SHLIB_MINOR) in the module's makefile, producing versioned output such as libfoo.so.X.Y with the usual symlink chain (libfoo.so -> libfoo.so.X -> libfoo.so.X.Y). This is consistent with CON-use-bsdmake's general instruction to reuse bsd.*.mk infrastructure where it fits rather than reinvent it -- here, reuse BSD's own established shared-library versioning convention directly, adapted to this project's mk.lib.mk. Exact per-OS behavior differences (FreeBSD's SHLIB_MAJOR vs. macOS's dylib versioning, which uses a different, Mach-O-specific mechanism) are not yet fully worked out -- open follow-up.
