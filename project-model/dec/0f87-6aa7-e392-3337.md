# PDF cluster membership is declared explicitly via a DOCWITH= macro per framework, not inferred from PREREQS= connectivity -- a full transitive-closure walk of PREREQS collapses into 'everything' for any non-leaf framework, the same failure mode as a single combined workspace PDF, so grouping must be a deliberate, curated declaration instead of derived from the dependency graph

Supersedes the connected-component-via-PREREQS idea proposed earlier in this same discussion (never recorded as an object, so no formal supersession needed -- just documenting why that direction was abandoned). Open detail not yet settled: is DOCWITH= symmetric/bidirectional (listing a framework in DOCWITH= automatically includes the reverse), and is it transitive (does A's DOCWITH= pull in B's own DOCWITH= list too) or does each framework's declaration stay exactly as curated? HTML generation is unaffected either way -- this is PDF-specific, since tag-file cross-linking doesn't need clustering at all.
