# End-user modules/frameworks built with Bmake It can declare and run their own unit tests, via an agnostic test orchestrator: a test declaration is a command -- built-then-run for compiled test sources, or a bare existing script/program -- plus exit-code check, timeout, and labels, agnostic to what produces the pass/fail, reporting to JUnit XML for CI compatibility

Carves this out of the general tests-docs-versioning-deferred-req blanket, matching the same pattern build-system-self-test-harness-req used to carve out Bmake It's own self-testing -- these are the two halves of that same original deferral, now both addressed. Informed by a comparison of CAA's own mkodt/RQC system (parallel .tst test frameworks, TestCases/OutputRef/SwitchTestCases, SetOdtParam for timeout/OS-exclusion/categorization, ODTInit for shared setup) against modern practice: the golden-file comparison and tiering/timeout/categorization ideas are still current (map onto CTest LABELS/TIMEOUT), but CAA's whole shell-script cross-platform-portability discipline is sidestepped by compiling real test binaries and reusing the existing run-target machinery for environment setup, rather than hand-writing portable shell.
