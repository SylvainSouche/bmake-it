# A name travels through make as one percent-encoded word; a path in a dependency line is relative to the module directory; a prerequisite framework make cannot name is reached through a link

Chosen over: (a) shell-quoted words in the lists (a hash cannot be stored with its backslash, and .for cannot take a hash at all); (b) lists in data files read by shell loops (the .for-unrolled recipes would all have to become shell, and make-level PREREQS handling stays); (c) refusing space and parentheses (they are the characters the user most expects to work, e.g. C:\Program Files (x86)). The encoding: space %20, hash %23, apostrophe %27, ampersand %26, parentheses %28 %29, equals %3D, brackets %5B %5D, tilde %7E, braces %7B %7D, percent %25; make side _BMK_ENC/_BMK_ENCW/_BMK_DEC in mk.common.mk, shell side bmk_enc/bmk_dec in scripts/bmk-names.sh, case 117 keeps them in agreement. Users write a space, apostrophe and hash in PREREQS=/PARENT_WS= with a backslash. Recipes write every directory for the shell with :Q. Dependency lines (headers in .d files, library files a relink waits for) hold only paths relative to the module directory; a prerequisite framework whose name or place has a space or parenthesis is reached through build/<key>/prereqs/<encoded name>. Known gaps, not tested by a case: docs (Doxygen TAGFILES), cross-test library directories, IMPORT= with a directory with a space, HTML dashboards (& not escaped).
