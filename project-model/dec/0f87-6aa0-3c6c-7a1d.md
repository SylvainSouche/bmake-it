# Once VM-based runtime verification exists for cross-compiled targets, the same approach should also be used for NATIVE host builds -- running the native test suite inside a VM of that host OS too, rather than directly on whatever machine happens to be running the harness, for consistency and reproducibility

User extended the VM-based verification approach to native builds as well, once the cross-target VM infrastructure exists: rather than running a macOS-native test suite directly on whatever Mac happens to be running the harness (with its own particular OS version, installed tools, environment quirks), run it inside a provisioned macOS VM -- and likewise for Linux-native and FreeBSD-native suites. This makes the testing environment for EVERY target (native and cross alike) a controlled, reproducible VM, rather than native builds being the one case still dependent on whatever the ambient host machine looks like.
