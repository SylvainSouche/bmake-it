# Bmake It failures must be loud and explained, as precisely as can be known: a nested order query that fails is a build error carrying the unit and bmake's own message, never a silent fallback to unsorted order; not finding sys.mk is an error naming every directory searched; a fetch failure reports, per URL, the tool used and its own message. Fix both root causes too: locate sys.mk from the invoking bmake's own search path (.SYSPATH) before any hardcoded list (which gains /usr/share/bmake/mk), and give a native-Windows curl a Windows path (cygpath -w) under Cygwin.
