# Framework/workspace 'all' and 'test' keep running every module/framework after one failure (unchanged default), but end with a nonzero exit and a named-failure summary; FAIL_FAST=yes is unaffected

Mechanism: reuse the existing per-module/per-framework build.failed marker file for the build side (already written, never read back). Add a symmetric test.failed marker, written by the SAME framework.mk/workspace.mk loop that already captures the real per-iteration exit code into $$_trc/$$_rc for test (mk.test.mk itself is untouched -- its own test: target already exits correctly; the marker only needs to persist that already-correct value across the one-shell-per-.for-iteration boundary, the same reason build.failed already exists). After the .for loop, a new _check_build_failures:/_check_test_failures: step scans for ${.CURDIR}/<child>/${BUILD_ROOT}/runs/${RUN_ID}/{build,test}.failed across every SUBDIR_MODULES/SUBDIR_FRAMEWORKS entry, prints one line per failed child naming its build.log/test-results.xml path, and exits 1 if any were found. Wired as the LAST prerequisite of all:/test: (after _aggregate/_aggregate_ws, and after the test dashboard block) so REPORT=yes dashboard generation and copy-up of whatever DID succeed are unaffected by the final failure -- only the overall target's own exit code changes.
