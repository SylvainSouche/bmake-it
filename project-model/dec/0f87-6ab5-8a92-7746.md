# Resolved import headers are copied (not symlinked, per this session's own established D6 precedent) into the SAME destination promoted generated headers already use (<fw>/build/<KEY>/include/), limited to exactly the names in IMPORT_HEADERS=; the resolved lib<LIB>.* files are copied into the module's own build/<KEY>/lib/, the same place a compiled library's own AR/link recipe already writes to

Only IMPORT_HEADERS= entries are staged, never the whole resolved include dir -- copying the entire prefix would leak every unrelated package under it and defeat PREREQS=-based visibility (matches the brief's own stated rationale). Re-staging is driven by item 4's inputs-hash mechanism: the resolved source/paths/version are folded into INPUTS_HASH_EXTRA=, so a changed env override, hook value, or newly-installed/upgraded system package triggers re-staging the same way a changed SANITIZE= triggers recompilation -- no separate cache-invalidation mechanism needed.
