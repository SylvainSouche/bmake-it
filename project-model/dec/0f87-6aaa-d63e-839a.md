# Bmake It's own mk/ role files are discovered by an out-of-tree project via bmake's native MAKESYSPATH mechanism, not MAKEFLAGS/-I -- a search path is the correct conceptual fit for shared/reusable make files (what <bsd.prog.mk>-style system includes already use, and what other bsd-make tooling on the same machine already relies on), not a general-purpose flags variable. Computed as MAKESYSPATH="<bmake-it>/mk:${MAKESYSPATH:-$(bmake -f /dev/null -V .SYSPATH)}" -- the -f /dev/null guard is required, not optional: bmake -V .SYSPATH alone fully parses whatever makefile happens to be in the current directory before printing the value, so any directory (including $HOME) with a stray or broken makefile silently corrupts the captured value. No change needed to mk/*.mk's own .include statements: BMK_MKDIR already auto-computes correctly via ${.PARSEDIR} regardless of whether the including file was found via a local relative path or via MAKESYSPATH -- verified against a real out-of-tree project with zero local Bmake It files and no BMK_MKDIR override anywhere
