# Characters in names and paths: what works anywhere works everywhere; the rest is refused upfront with an explanation

Decided with the user. (1) A character that is tested to work on a platform is valid and must be supported on every platform, and tested on every platform. A mixed result (= works under Debian's bmake, builds nothing under macOS's and Alpine's) is fixed so that it works everywhere, not refused. (2) A character that works nowhere is tested upfront -- before any build step, clean included -- and refused with a message that names the character, the directory and the characters that do work. (3) Exception: characters evidently expected to work are supported (fixed), not refused, although they fail today: space, parentheses ( ), apostrophe ', ampersand & and hash #. Comma is NOT in that set and is refused. (4) Never a silent success. Placement matters: a character is judged where it was measured to work (braces work in workspace and mk-directory names, not in module names; # ! : , = * ? work in the mk directory name, not in workspace/framework/module names). Until the must-work characters are fixed they are refused with a 'not supported yet' message, so the failure is graceful.
