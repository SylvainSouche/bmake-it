# make port is fundamentally different from make pkg/deb/rpm: it generates a SOURCE-based build recipe (Makefile, distinfo, patches, pkg-plist) for the ports system to fetch/patch/build itself, not a staged binary package; the install-into-distrib mechanism (REQ-packaging-invokes-install-into-distrib-req) applies only to binary-package-style targets

User corrected an overgeneralization: REQ-distrib-dir-for-packaging-staging-req and REQ-packaging-invokes-install-into-distrib-req (stage via install DESTDIR=distrib/KEY, then build the package from that staged tree) describe how BINARY package formats work (pkg, deb, rpm, msi -- an already-built artifact gets wrapped/archived into an installable package). A BSD-style port is categorically different: it is source-code-based (typically a fetch/download step), plus patches, plus the ports systems own build tooling -- the port itself contains no pre-built binaries, only a recipe (Makefile, distinfo checksums, patch files, and a pkg-plist enumerating what an eventual build would install). Consequently, make port does NOT stage from distrib/KEY the way make pkg/deb/rpm do; it needs a substantially different mechanism (generating/templating port metadata files, referencing this projects own source location, possibly deriving pkg-plist from a distrib/KEY dry-run without embedding the actual binaries). This is now an explicit open design item, not assumed to follow the same pattern as the binary-package targets.
