# Debug vs release is not a single MODE= switch; it is controlled via real bsd makes own existing flag variables (DEBUG_FLAGS for debug symbols, optimization-level flags for release), reused as-is rather than wrapped in a new abstraction

User chose to reuse bsd makes own native convention rather than invent a unified debug/release toggle (unlike TOOLCHAIN=, which WAS a new project-specific variable because bsd make has no native toolchain-bundle concept -- REQ-toolchain-cli-variable-req). Real bsd.*.mk already exposes DEBUG_FLAGS (typically -g, for debug symbol generation) and optimization-level flags (e.g. COPTFLAGS/CFLAGS-style overrides for -O0 vs -O2) as ordinary overridable variables. Rather than wrapping these in a new MODE=debug|release abstraction, the project reuses them directly: a developer sets DEBUG_FLAGS=-g and/or overrides the optimization flags variable(s) explicitly, the same way they would in any bsd.*.mk-based project. Exact variable name(s) for optimization-level control (COPTFLAGS vs CFLAGS vs something else) need verification against real bsd.*.mk source -- joins the standing empirical-check item (OBS-cache-mechanism-needs-empirical-check).
