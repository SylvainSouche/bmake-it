# Header visibility is three levels, not two: framework/include (public, to prereq-declaring frameworks), framework/local/include (to all of the framework's own modules), module.m/include (to that module's own sources only)

User added a third visibility level beyond the earlier-confirmed two-level model (REQ-framework-header-exposure): a module can now also have its own private include/ directory, visible only to that module's own source files -- not to sibling modules in the same framework, and not to other frameworks. This gives three levels total: (1) framework/include/ -- public, visible to any framework that lists this one as a prereq; (2) framework/local/include/ -- visible to all of this framework's own modules; (3) module.m/include/ -- visible only within that one module. This does NOT reopen NREQ-no-four-level-header-visibility: that NREQ specifically rejected real mkmk's four-level Public/Protected/Private/Local scheme (which has a distinct Protected cross-framework-partial-visibility level and enforced include-direction checks). This new three-level scheme is a different, simpler shape -- no Protected level, no enforced checks decided yet -- so it is recorded as a supersession of the earlier 2-level REQ, not a reversal of the NREQ.
