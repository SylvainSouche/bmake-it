# Add real per-source header dependency tracking to mk.prog.mk/mk.lib.mk: gcc/clang -MMD -MP -MF<obj>.d per compile, conditionally .include'd; MSVC stays an explicit, documented limitation for now

Mechanism: every gcc/clang compile recipe in mk.prog.mk/mk.lib.mk (plain .c/.cc/.cpp/.cxx, and the yacc/lex-generated .c step, for uniformity) additionally passes -MMD -MP -MF ${_OBJDIR}/${_s:R}.d. Each object's own .d file is conditionally .include'd -- `.if exists(...) .include "..."` per source in a .for loop, NOT bmake's newer `.dinclude` directive, since `.dinclude`'s availability on the phase-1 FreeBSD/NetBSD base-make targets (REQ-phase1-concrete-targets) hasn't been empirically checked and can't be from this host (macOS only) -- plain conditional .include is the more conservative, universally-documented bmake idiom and achieves the same effect (silently absent on a fresh build before any .o exists, present and consulted on every rebuild after).

Gated to TOOLCHAIN != msvc: msvc-cc-wrapper.sh translates only the specific gcc-style flags it explicitly recognizes (SANITIZE=address's spelling) to cl.exe equivalents; an unrecognized -MMD/-MP/-MF would pass through literally and likely error. MSVC's real equivalent is /showIncludes (stdout-based, not a generated .d file) -- implementing that needs wrapper-side stdout parsing to synthesize an equivalent dependency file, a materially different mechanism from the gcc/clang path, deferred rather than half-implemented this round (msvc-header-dependency-tracking-deferred, separate OBS).

No clean: change needed: ${_OBJDIR} already lives under ${BUILD_ROOT} (OBJDIR = ${BUILD_ROOT}/obj), which clean: already rm -rf's entirely -- confirmed by reading the existing target, not assumed.

Also authorizes superseding REQ-compiler-native-dependency-tracking-req (0f87-6a91-4c89-ba40): its confirmed-working claim, even where accurate about real bsd.sys.mk's own canned suffix rule, does not describe a mechanism Bmake It's own explicit-recipe mk.prog.mk/mk.lib.mk ever reaches (see header-dependency-tracking-not-wired-for-real).
