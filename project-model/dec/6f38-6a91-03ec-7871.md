# Before invoking the linker for a module with LIBS= entries, an explicit check verifies each referenced library has actually been built; a missing dependency produces a clear, explicit 'not yet built/linked' diagnostic rather than relying on the linker's own generic missing-library error

User proposed a defensive guard at the moment of linking: rather than relying purely on the order cache (REQ-order-target-blank-run-req) always being correct and trusting the linker's own error message if something is out of order (e.g. a stale cache, a partial/manual build, or a genuine bug in order resolution), explicitly check that each LIBS= entry a module depends on has actually produced its build artifact before attempting to link, and fail with a clear, specific diagnostic naming the missing dependency if not. This is a fail-fast safety net layered on top of the already-correct ordering guarantee (REQ-fused-build-per-module-full-dependency-order-req), not a replacement for it -- in the normal case this check always passes, since the order cache should already have sequenced the build correctly.
