# Tests may also be organised as .tst modules inside a framework, as the escalation path beyond the flat tests/<name>.cpp default: a <name>.tst directory sits beside the .m modules, has the module shape (makefile, src/, testcases/), and so carries its own build directives (LIBS=, flags, several sources, helper programs) -- unlike a loose test source with none. Scripts in testcases/ are the tests; PROG= names a utility program they use; TEST_PROG=<name> names a program that is itself an ATF test program; one module may have both macros and any number of scripts. A nested test framework was considered and rejected (needs recursive discovery and its own PREREQS=)
