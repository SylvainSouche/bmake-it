# For now Bmake It links none of its own code into the programs and libraries it builds: no runtime support library (such as a delay-load failure hook), because that would make Bmake It responsible for, and committed to maintaining and supporting, code that ships inside its users' products

What Bmake It builds for tests only (the ATF it carries, contrib/atf-bmk) never ships in a product. Delay loading therefore uses the toolchain's own behaviour: a missing DLL at the first call ends the program (exit 127, no message); a program that wants a message defines __pfnDliFailureHook2 itself -- documented, with the example.
