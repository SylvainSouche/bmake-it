# Before running tests (and by extension, before a real build), required tools (compilers, linkers, yacc/lex, resource compilers, mkdep, etc.) must be checked for presence; if a required tool is missing, either install it automatically or produce a meaningful diagnostic naming exactly what is missing and how to obtain it -- never fail with an opaque command-not-found error

Extends the graceful-failure principle specifically to build-tool availability: the test harness (and, by the same principle, the build system itself) must verify that every tool a given test case or build actually needs is present before attempting to use it. Where a missing tool CAN be reasonably auto-installed (e.g. via the hosts own package manager -- apt/MacPorts/pkg), the harness should attempt that automatically; where auto-install is not appropriate or not possible (e.g. a proprietary toolchain like real MSVC), it must produce a clear, specific diagnostic identifying exactly which tool is missing and pointing to how a human would obtain/install it -- never an opaque shell-level command-not-found failure.
