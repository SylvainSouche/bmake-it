# Toolchain compiler detection must search PATH (or a defined list of install prefixes) and fail loudly when the requested toolchain's compiler cannot be found, never silently substitute a different compiler by falling through a hardcoded single-path check

Same principle as DEC-nested-invocation-reentrancy-guard-dec, applied to a different mechanism: a hardcoded absolute path standing in for what should be a robust lookup is a recurring failure shape in this implementation, not a one-off. Silently substituting gcc when the user asked for llvm is worse than erroring, because the build appears to succeed while quietly not doing what was requested -- exactly the kind of drift this project's own discipline exists to prevent.
