# Two new IMPORT= kinds, fetch:<name> (source) and fetch-bin:<name> (prebuilt release), modeled on real FreeBSD ports' own fetch/verify/extract/patch split (MASTER_SITES+DISTFILES+distinfo+WRKSRC+files/patch-*, confirmed via the Porter's Handbook, not copied) but reimplemented: only a per-module distinfo-style checksum file and any patches are committed; the fetched distfile and its extracted work tree never are

Confirmed against the real mechanism (FreeBSD Porter's Handbook, fetched 2026-09-25, not assumed from memory): MASTER_SITES (mirror URLs) + DISTNAME/DISTFILES (the distfile's own name) live in the port's Makefile; distinfo is a separate, minimal committed file, one TIMESTAMP line plus one SHA256(file)=hex / SIZE(file)=bytes pair per distfile; the distfile itself downloads into a local cache (distfiles/), never the ports tree; WRKDIR/WRKSRC is a scratch extraction directory, also never committed; files/patch-* ARE committed (the porter's own transformation, not the upstream's copyrighted content) and apply relative to WRKSRC.

Bmake It's own version keeps that exact split (fetch-location macros in the makefile/mk-hooks; distinfo purely as checksums; patches committed; distfile cache and extracted work tree both gitignored, never committed) but is NOT a copy of bsd.port.mk's own code or variable names beyond what's already generic build-tooling vocabulary (the same "original implementation, not adapted from prior art" stance already taken for mk.qt.mk, qt-mechanism-original-implementation).

Key architectural choice from the user's own clarification, not assumed: the SOURCE kind (fetch:) does not shell out to the upstream project's own build system (no ./configure, no cmake) -- the extracted (and optionally patched) files become this module's own SRCS, compiled through Bmake It's existing compile pipeline exactly like a .y/.l grammar's generated .c already is. This keeps the "no third-party build-system plumbing" stance (already established for Qt, qt-development-without-plumbing-req) consistent across every external-code mechanism in the project, not just Qt's.
