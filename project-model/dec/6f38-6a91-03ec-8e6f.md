# The default make (build) target automatically runs make order first if the cache is missing or stale, so a fresh checkout builds correctly with plain make; make order remains available as its own explicit target for inspection/debugging

User confirmed the order cache is auto-triggered rather than requiring a mandatory manual step: unlike REQ-mkdep-style-header-dependency-tracking-req's per-source .depend (which is purely an incremental-rebuild OPTIMIZATION -- a build works correctly without it, just less efficiently), the order cache is NECESSARY information for the build to know what sequence to build things in at all -- without it, the underlying bsd.subdir.mk-based recursion (REQ-dep-order-generation-mechanism-req) has nothing to work from. So the default make target has the order cache as an implicit prerequisite: if missing or detected stale, make order runs automatically first, then the build proceeds -- a fresh checkout Just Works with plain make, no separate mandatory step. make order remains independently invocable for inspecting the resolved build order without triggering an actual build.
