# Compiler/linker sanitizer instrumentation (AddressSanitizer, UndefinedBehaviorSanitizer, ThreadSanitizer, MemorySanitizer, LeakSanitizer) is selected via a SANITIZE= build variable (comma-separated, e.g. SANITIZE=address,undefined), composing with both make run and make test since it's a general compile/link-flag concern, not test-specific

Mutually-exclusive combinations (e.g. address+thread, address+memory) must fail loudly rather than passing invalid flags through to the compiler for a cryptic error, matching the existing cross-target-selection-must-fail-loudly-req discipline. Toolchain/platform support varies genuinely: gcc/clang on Linux/macOS/BSD have full support; MSVC has AddressSanitizer only (recent versions, Windows-specific quirks); mingw/Cygwin support is patchy. Must be documented as explicit limits per the universal-coverage REQs' discipline, not silently degraded.
