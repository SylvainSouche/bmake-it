# A cross-compiled binary cannot run on the build host, so verifying its RUNTIME behavior (not just that it compiled) requires provisioning and running it on a VM of the target platform; this must happen without user intervention, OR -- if full automation is not achieved -- be clearly documented, with the harness itself detecting whether the required VM environment is present and, if not, directing the user to that documentation rather than failing silently or cryptically

User identified a real gap: the full cross-build-matrix decision only verifies a cross-built binary compiles and links, since it cannot be executed directly on the build host. To achieve the runtime-verification bar already set for native builds, a VM of the target platform must be provisioned and the binary actually run inside it. Two acceptable outcomes, in priority order: (1) fully automated -- VM provisioning and execution happens with no user intervention, as part of running the harness; (2) if full automation is not achieved (e.g. licensing constraints on certain VM images), the setup must be clearly documented, AND the harness itself must detect whether the required VM environment is actually present/configured, failing gracefully with a pointer to that documentation rather than a cryptic failure when the environment is missing.
