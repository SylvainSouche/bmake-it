# Module name case-sensitivity follows the host filesystem's own case sensitivity (e.g. distinct on case-sensitive FS, potentially colliding on case-insensitive FS)

User clarified that module names (and by extension the .m directory names, REQ-module-dir-naming-convention) are only as case-sensitive as the underlying OS's filesystem. On a case-sensitive filesystem (typical Linux/FreeBSD, and macOS when configured case-sensitive), Hello.m and hello.m are distinct modules. On a case-insensitive (but usually case-preserving) filesystem -- macOS's default HFS+/APFS configuration, or Windows-adjacent filesystems under Cygwin/WSL -- they would collide/refer to the same directory. This is a property inherited from the OS, not something the build system enforces or overrides itself.
