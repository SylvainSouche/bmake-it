# A working prototype confirms the dependency-ordered SUBDIR generation mechanism: query each module makefiles LIBS= in isolation via bmake -f <dir>/makefile -V LIBS, topologically sort with Kahn algorithm ignoring out-of-framework references, emit a generated SUBDIR= .mk fragment consumed by bsd.subdir.mk

Built and tested a real POSIX-shell prototype (gen-mod-order.sh) implementing the previously-undesigned piece flagged as the top implementation blocker: turning module LIBS= dependency declarations into an actual build order for bsd.subdir.mk (which itself has no topological-sort concept, only processes whatever SUBDIR list it is given). Mechanism, confirmed working end to end: (1) discover *.m module directories by scanning (REQ-modules-and-frameworks-auto-discovered-req); (2) query each modules LIBS= in isolation via  -- confirmed this correctly reads the variable without triggering a build; (3) run Kahns algorithm treating LIBS= entries as edges, silently ignoring any entry that is not one of the discovered *.m module names (an out-of-framework reference, e.g. a PREREQS-resolved framework library, correctly out of scope for this graph -- confirmed with a real test: LIBS=System where System is not a local module built successfully with no complaint); (4) emit the sorted order to a generated .mk fragment (SUBDIR=modA.m modB.m ...), which the framework makefile .includes before .include <bsd.subdir.mk>; (5) bsd.subdir.mk was confirmed to recurse in exactly the SUBDIR declaration order, building a 4-module chain (A<-B<-C<-D, with C depending on both A and B) in the correct order every time; (6) a genuine cycle (X depends on Y, Y depends on X) was confirmed to be detected cleanly -- the script exits non-zero with a clear diagnostic rather than hanging or silently producing a broken/partial order. This directly answers the previously-open top implementation blocker and gives a concrete, tested mechanism to build mk.framework.mk and mk.workspace.mk on. The same mechanism generalizes directly to workspace-level framework ordering via PREREQS= (REQ-framework-build-order-follows-prereqs-graph-req) -- same algorithm, framework directories and PREREQS= instead of module directories and LIBS=.
