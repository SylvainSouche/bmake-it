# make order (workspace level) is an explicit target that performs a blank run -- no compilation or linking, just discovery + PREREQS/LIBS graph resolution across the whole workspace -- writing the result to a cache that the build target then consumes, instead of resolving order inline on every build

User proposed formalizing the previously-implicit dependency-order generation (REQ-dep-order-generation-mechanism-req) as its own explicit, named target: make order, run at workspace level. It performs a single blank run across the entire workspace -- scanning every framework and every module within each framework, reading PREREQS= (REQ-framework-prereqs-macro-req) and LIBS= (REQ-libs-macro-link-only-headers-via-prereqs-req) -- and resolves the COMPLETE dependency graph in one pass: framework build order (via PREREQS) and, for each framework, its modules' build order (via LIBS). No source is compiled and nothing is linked during this run; the only output is a generated order cache. The actual build (default make target) then reads and uses that cache rather than re-resolving anything inline. This gives REQ-prereqs-resolution-cached-like-depend-reqs 'explicit or detected-stale trigger' an explicit, named form: make order IS that trigger.
