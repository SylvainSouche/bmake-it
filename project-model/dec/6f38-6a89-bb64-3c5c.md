# Toolchain (gcc vs llvm) gets its own slot in the build directory key, coexisting like separate OS/arch targets

User confirmed that a single OS+arch pairing built with two different toolchains (gcc, llvm) must be able to coexist in the same source tree without collision, the same way two different OS/arch targets coexist. This means the directory key driving build/<KEY>/ throughout the tree (REQ-build-output-tree-structure) is not just OS+arch -- it must also include toolchain. The bare term '$OS_ARCH' used so far undersells this; going forward the key should be thought of as a compound target identifier (OS, arch, toolchain), tentatively written as something like <os>-<arch>-<toolchain> (e.g. macosx-arm64-llvm, macosx-arm64-gcc, freebsd-x64-gcc, freebsd-x64-llvm). Exact separator/format is still open -- naming scheme not yet finalized. This does NOT reopen the earlier variant decision (REQ-variant-out-of-scope-for-dirtree): build variant (debug/release) still does not get a slot, only toolchain does.
