# A separate trigger generates internal-scope documentation -- public plus framework-local headers (fw/local/include/), not just public -- for the framework's own developers, and doubles as a quality-assurance gate: Doxygen's own documentation-completeness warnings (undocumented/incomplete entries) are escalated to hard failures in this mode rather than left as informational warnings

Distinct from CAA's own -private/-docPrivateMember flags, which include PrivateInterfaces -- Bmake It's own vocabulary distinguishes local (framework-wide-internal, fw/local/include/) from private (module-only, module.m/include/); this trigger is scoped to public+local specifically, per the user's wording. Whether module-private headers should also be included in this QA mode is not yet settled.
