# Staging share/ resources for a target is a three-layer overlay copy: share/common/, then share/<os>/, then share/<os>_<arch>/, each layer overwriting same-named files from the previous one

Refines REQ-share-dir-fallback-hierarchy with the exact staging mechanism: the target build share/ output is produced by copying share/common/ first, then copying share/<os>/ over it (same-named files get overwritten, unique files from each layer are preserved), then copying share/<os>_<arch>/ over the result. Net effect: any file present at multiple specificity levels ends up as the most specific version, while files unique to a less-specific level still make it into the final staged output. This matches the copy-based aggregation mechanism already decided for bin/lib (REQ-aggregation-step-copies-outputs) -- share/ staging uses the same copy-based approach, just layered by specificity rather than by module/framework/workspace level.
