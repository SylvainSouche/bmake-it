# FETCH_BUILD=autotools|cmake|meson|custom on an IMPORT=fetch: module delegates the extracted+patched source to its own upstream build system instead of SRCS=, installing into a module-local prefix (work/_install) and staging the result exactly like fetch-bin: (via the same _stage_import: mechanism)

Named presets run a sensible default recipe: `autotools` is
`./configure --prefix=<local prefix> [--host=<cross triple>] $FETCH_BUILD_ARGS
&& make && make install`; `cmake` is `cmake -S -B ... -DCMAKE_INSTALL_PREFIX=
$FETCH_BUILD_ARGS && cmake --build && cmake --install`; `meson` is
`meson setup --prefix=... $FETCH_BUILD_ARGS && meson compile && meson
install`. `FETCH_BUILD=custom` runs `FETCH_BUILD_CMD=` verbatim (cwd the
resolved work tree; `BMK_FETCH_SRCDIR`/`BMK_FETCH_BUILD_DIR`/
`BMK_FETCH_INSTALL_PREFIX` exported) for anything else (SCons, a
hand-rolled script, a second-tier build tool). Chosen over presets-only
(too narrow -- real fetched projects use every build system) and over
custom-only (no built-in autotools/cmake/meson knowledge means every
module re-writes the same configure/build/install boilerplate).

Bmake It's own `CC`/`CXX`/`CFLAGS`/`CXXFLAGS`/`LDFLAGS` are exported as
environment variables into the build invocation, so the upstream project
builds with the SAME compiler Bmake It is using -- all three presets
honor these natively for a *native* build. For a cross build under
`TOOLCHAIN=llvm`, `CC`/`CXX` already carry clang's `--target=`/
`--sysroot=` (mk.toolchain.llvm.mk's own `_CROSS_FLAGS`), which works
correctly for autotools (`--host=<triple>` derived from the same
`_CROSS_FLAGS`, plus the flags-laden `CC` autotools already knows how to
use as-is). CMake's `-DCMAKE_C_COMPILER=`/Meson's compiler detection
both expect a bare executable path, not a flags-laden string, so
cross-compiling via `FETCH_BUILD=cmake`/`meson` is NOT correctly
supported yet (a `CMAKE_TOOLCHAIN_FILE`/Meson cross-file generator would
be needed) -- documented as deferred in `26-fetched-external-sources.md`,
not silently broken: the native case works fully, cross under cmake/
meson does not error but will silently miss the cross flags.
