# Copy-up collision handling is diff-aware: identical files copy silently; differing files that are a genuine (non-overlay) collision emit a warning but the build still proceeds (overwrite, not hard error); the deliberate share/ specificity overlay is exempted from warnings entirely since it is expected, by-design behavior

Refines the copy-up mechanism (REQ-aggregation-step-copies-outputs, module/framework/workspace bin/lib copy-up) and the share/ overlay (REQ-share-overlay-copy-order) with a unified collision policy: byte-identical source/destination -> silent, no message. Differing content, NOT explained by the deliberate share/ specificity cascade (common -> os -> os_arch) -> emit a warning identifying the colliding artifact and its sources, but do NOT stop the build -- the copy proceeds (last-copied-wins, following whatever order the aggregation naturally runs in). Differing content THAT IS explained by the share/ specificity cascade (a more-specific variant intentionally overwriting a less-specific one) -> no warning at all, this is expected behavior, not a collision. Exact warning message wording/format not yet specified -- open follow-up for implementation.
