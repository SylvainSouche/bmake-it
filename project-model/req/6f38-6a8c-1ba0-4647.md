# make port produces a source-based build recipe (Makefile/distinfo/patches/pkg-plist) for the ports system to build from source, NOT a staged binary package; REQ-packaging-invokes-install-into-distrib-req applies only to binary-package-style targets (pkg, deb, rpm, msi)

Narrows the scope of REQ-packaging-invokes-install-into-distrib-req and REQ-distrib-dir-for-packaging-staging-req: those describe binary-package targets only (pkg, deb, rpm, msi -- REQ-packaging-per-format-targets-req). make port is a distinct category: it generates the BSD ports-style recipe (a port Makefile, distinfo with source checksums, any needed patch files, and a pkg-plist enumerating installed paths) that points at this projects own source (typically for the ports systems own fetch step), rather than staging or embedding any pre-built binary. Exact mechanism for make port -- how source is referenced/packaged for fetching, how pkg-plist gets generated (possibly from a distrib/KEY dry-run, without embedding the binaries themselves), and the ports Makefile template itself -- is NOT yet designed, explicit open follow-up.
