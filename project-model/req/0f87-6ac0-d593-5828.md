# For the selected target and toolchain, entries are evaluated in this order and the first that applies decides: (1) a loud negative '!-x' matching -> error; (2) a quiet negative '-x' matching -> the module is skipped; (3) if any positive entry exists and none matches -> skipped, or an error if any positive entry is loud ('loud wins'); otherwise built. A more specific entry beats a more general one (linux -linux_arm64 excludes linux_arm64). A skip prints one informational line and exits 0 (tests skipped with the module); an error stops the build. Both axes are evaluated and the error outcome wins over a skip
