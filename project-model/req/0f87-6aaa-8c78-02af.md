# mk.qt.mk: QT_MODULES=<names> (e.g. Core Widgets Gui, no Qt5/Qt6 prefix) resolves compile/link flags via pkg-config against Qt${QT_VERSION}<name> (QT_VERSION defaults 6, overridable to 5), the same pkg-config-based discovery pattern already used for atf-c++/atf-c -- not qmake -query. .ui and .qrc files are auto-discovered from src/ like .y/.l; MOC input is NOT a declared macro but auto-discovered by scanning the module's own include/*.h for Q_OBJECT/Q_GADGET/Q_NAMESPACE. Generated-file destinations closely mirror the existing yacc/lex convention (generated-headers-in-build-tree-req): .ui produces ui_<name>.h in the module's own build/<KEY>/obj/, copied to build/<KEY>/include/ (private by default, promotable via INCL= exactly like a yacc header); a Q_OBJECT header produces moc_<name>.cpp compiled straight from build/<KEY>/obj/ (no header, not INCL=-promotable, same as yacc's .c half); .qrc produces qrc_<name>.cpp the same way
