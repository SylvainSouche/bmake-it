# Per-source header dependency tracking is fully native and requires no custom wiring: bsd.sys.mk already passes -MD -MF.depend.<obj> to the compiler on every ordinary compile, producing correct per-object dependency files automatically, confirmed to correctly drive incremental rebuilds when a shared header changes. Supersedes the earlier REQ-mkdep-tool-works-wiring-must-be-custom-req, which was based on testing the wrong mechanism (the separate make depend target/mkdep tool, not the compiler-native path that actually matters)

Corrects REQ-mkdep-tool-works-wiring-must-be-custom-req: mk.prog.mk/mk.lib.mk do NOT need a custom depend: target invoking mkdep manually. Real bsd.sys.mk already wires the compiler's own -MD flag into every compile (CFLAGS/CXXFLAGS get -MD -MF${DEPENDFILE} equivalents automatically), producing a per-object .depend.<objname> file as a side effect of ordinary compilation -- no separate step, no external tool invocation, confirmed correctly triggering recompilation of exactly the affected objects when a shared header changes. This restores REQ-mkdep-style-header-dependency-tracking-req's original assumption (reuse real bsd.*.mk infrastructure, per CON-use-bsdmake) as CORRECT after all -- the earlier correction narrowing it to custom shell-script wiring was itself based on an incomplete test and is now reversed. The classic mkdep tool and the depend: target remain present in bsd.dep.mk for other/legacy purposes (their exact modern role not further investigated) but are NOT what mk.prog.mk/mk.lib.mk need to rely on for incremental header-dependency tracking.
