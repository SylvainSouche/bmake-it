# Within a framework, module compilation (src/ to obj/) is fully order-independent/parallelizable since headers never come from sibling modules; only the link step of a module is ordering-constrained, and only with respect to sibling modules it names in LIBS=

Refines/narrows REQ-framework-build-order-follows-prereqs-graph-req when applied within a single framework: sibling-module ordering is NOT a whole-build-order concern the way framework-level PREREQS is. Compiling a module never depends on any sibling module (headers come only from the modules own include/, the frameworks local/include/, and PREREQS-declared frameworks -- REQ-headers-resolved-from-source-req, REQ-generated-headers-in-build-tree-req), so all of a frameworks modules can compile in parallel, in any order. The link step of a module IS ordering-constrained, but scoped narrowly: it must wait only for whichever sibling modules it names in its own LIBS= (REQ-libs-macro-link-only-headers-via-prereqs-req) to have already produced their linked artifact.
