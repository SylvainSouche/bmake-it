# A framework's build/<key>/{include,bin,lib,share} directories must exist before ANY module in that framework is built, in every pass -- not just after the first pass's _aggregate runs. Root cause (found via direct reproduction, not assumed): mk.prog.mk/mk.lib.mk gate -I<fwdir>/build/<key>/include onto CFLAGS/CXXFLAGS with a parse-time exists() check; framework-level all: lists _build_modules BEFORE _aggregate (which creates that directory), so a module parsed during the FIRST pass (directory absent) gets no such -I flag, while the SAME module parsed during a SECOND, fresh bmake pass (directory now exists, created by the first pass's _aggregate) silently gains one -- changing CFLAGS content between passes, which changes _check_inputs_hash's fingerprint, forcing a spurious recompile and re-archive, whose new embedded ar timestamp then differs from the already-copied-up archive, producing a 'copy-up collision ... differs -- overwriting' warning on an otherwise genuinely clean, unchanged build
