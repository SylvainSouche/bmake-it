# A module supplies additional compile or link options by appending directly to bsd makes own native CFLAGS/CXXFLAGS/LDFLAGS/YFLAGS/LFLAGS variables in its makefile (e.g. CFLAGS+=-DFOO); no project-specific LOCAL_*FLAGS wrapper macros exist

Supersedes REQ-flags-reuse-bsd-native-vars-req (unchanged content, re-pointed ancestor only). Closes REQ-module-makefile-fields' original additional compilation or link options provision with a concrete mechanism: standard bsd make variables (CFLAGS, CXXFLAGS, LDFLAGS, YFLAGS, LFLAGS for the in-scope languages per REQ-supported-languages) are used unchanged, extended via ordinary += in a module makefile. This is consistent with the project's general principle of reusing bsd-make-native variables wherever they already exist, applied identically to how TARGET=/TARGET_ARCH=, DESTDIR/PREFIX, and DEBUG_FLAGS/optimization flags were handled.

Why this exists as a supersession rather than an edit: this REQ genuinely refines REQ-module-build-macros-req -- that REQ specifies which macros a module's makefile holds (PROG=/LIB=/LIB_SHARED=/LINK_WITH=), and this REQ is the more precise statement that the makefile can *also* append to existing bsd-native macros on top of declaring those project-specific ones. The `refines` edge itself was correct; only its target needed to move once the v1->v2 migration marked REQ-module-build-macros-req superseded without updating objects that refined it (DEC-view-drift-refines-repoint-dec). REQ-module-build-macros-req was split across two successors -- REQ-module-prog-or-lib-macro-req (the PROG=/LIB= declaration facet this REQ refines) and REQ-libs-macro-link-only-headers-via-prereqs-req (the unrelated LIBS=/LINK_WITH= facet) -- so `model.py supersede` correctly refused to guess and the refines edge was added explicitly via `model.py link`. No content changed.
