# mk.prog.mk/mk.lib.mk define fully explicit ${_OBJDIR}/${_s:R}.o: ${.CURDIR}/src/${_s} compile rules with hand-written recipes, and never .include bsd.sys.mk, bsd.prog.mk, bsd.lib.mk, or any other real bsd.*.mk file -- confirmed by grepping every .include across mk.common.mk/mk.prog.mk/mk.lib.mk/mk.framework.mk/mk.workspace.mk. Real bsd.sys.mk's own -MD/-MF wiring (present on FreeBSD, confirmed absent from NetBSD's bundled mk-netbsd set, MacPorts status now moot) therefore never applies to this project's own compiled objects on any host -- header dependency tracking needs its own explicit mechanism, not inherited reuse. See header-dependency-tracking-req for what was actually built.

Supersedes 6f38-6a91-4c89-ba40 (Per-source header dependency tracking is fully native and requires no custom wiring: bsd.sys.mk already passes -MD -MF.depend.<obj> to the compiler on every ordinary compile, producing correct per-object dependency files automatically, confirmed to correctly drive incremental rebuilds when a shared header changes. Supersedes the earlier REQ-mkdep-tool-works-wiring-must-be-custom-req, which was based on testing the wrong mechanism (the separate make depend target/mkdep tool, not the compiler-native path that actually matters)).

Carries forward what remained valid and states what changed.
