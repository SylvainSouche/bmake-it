# PARENT_WS and PREREQS resolution results are cached in a generated, auto-.included .mk fragment (modeled directly on real bsd makes .depend mechanism), not recomputed by walking the filesystem on every make invocation

Confirms a caching strategy for the workspace-level build-sequence steps that resolve PARENT_WS (REQ-workspace-parent-macro-absolute-req) and each frameworks PREREQS (REQ-framework-prereqs-macro-req) -- both header search paths and build order (REQ-framework-build-order-follows-prereqs-graph-req). Rather than re-walking workspaces and framework makefiles on every make invocation, results are written to a generated .mk file that gets .included automatically, exactly mirroring real bsd makes .depend idiom (a generated file, regenerated via an explicit step, consumed via .include on later runs) -- consistent with reusing bsd.*.mk infrastructure (CON-use-bsdmake). Open follow-ups for the implementation phase: exact generated filename, staleness-detection mechanism, and whether regeneration is triggered explicitly (an analog to make depend) or auto-detected.
