# make order performs a workspace-wide blank run (discovery + full PREREQS/LIBS dependency-graph resolution, no compilation or linking) and writes the topologically-sorted result to a cache; the build target consumes that cache rather than re-resolving order inline

Formalizes REQ-dep-order-generation-mechanism-req and REQ-prereqs-resolution-cached-like-depend-req into an explicit workspace-level target. make order: (1) auto-discovers every framework at the workspace root and every module within each framework (REQ-modules-and-frameworks-auto-discovered-req); (2) reads each frameworks PREREQS= and each modules LIBS=; (3) resolves the complete dependency graph -- framework-level order via PREREQS, module-level order within each framework via LIBS -- using the same topological-sort mechanism already prototyped (prototypes/gen-mod-order.sh); (4) writes the sorted result to a generated cache (the same artifact referred to at a policy level in REQ-prereqs-resolution-cached-like-depend-req). No compilation, linking, or header generation happens during this run -- it is purely discovery and graph resolution. The default make (build) target reads this cache to drive its own SUBDIR-based recursion, rather than resolving order itself on every invocation.
