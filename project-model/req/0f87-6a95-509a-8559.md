# When PROG= or LIB= is not set in a module's makefile, it defaults to the module's directory name with the .m suffix stripped; for LIB= specifically, a leading 'lib' prefix on that name is also stripped (e.g. libgreet.m defaults to LIB=greet, not LIB=libgreet)

Supersedes REQ-prog-lib-default-to-module-name-req-v2 (extends it; the PROG= defaulting rule is unchanged). Refines REQ-module-prog-or-lib-macro-req and REQ-module-dir-naming-convention: a module directory named NAME.m defaults to PROG=NAME (if .include <mk.prog.mk>) when PROG= is left unset. For LIB= (if .include <mk.lib.mk>) when left unset, the default is NAME with the .m suffix stripped, AND, if that name starts with 'lib', that leading 'lib' is also stripped -- so libgreet.m defaults to LIB=greet, not LIB=libgreet.

Why this exists as a supersession rather than an edit: the prior version only specified stripping '.m'. Found while assessing the impl/ implementation, which additionally strips a leading 'lib' -- real bsd.lib.mk/mk.lib.mk conventions prepend 'lib' when naming output (lib${LIB}.so, lib${LIB}.a), so defaulting LIB= to the full 'libgreet' would produce a redundant liblibgreet.so. The user confirmed this should be the spec, not merely an implementation convenience (DEC-lib-default-strips-lib-prefix-dec) -- this is new precision added to the requirement, not a correction of wrong content, so it is recorded as a supersession per the model's own discipline (supersession is total; nothing here was wrong, it was incomplete).
