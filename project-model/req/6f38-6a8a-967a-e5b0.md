# Header search paths for a framework are built directly from the include/ directories of the frameworks listed in its PREREQS (resolved locally first, then via PARENT_WS in order); build/<KEY>/ is never consulted for headers

When compiling within a framework, the header search path includes: (1) its own local/include/ and, for each module, that modules own include/ (REQ-three-level-header-visibility-req); (2) for each framework named in its PREREQS= (REQ-framework-prereqs-macro-req), that frameworks include/ directory -- resolved by finding the prereq framework first within the current workspace, then falling back through PARENT_WS workspaces in declared order (REQ-workspace-parent-macro-absolute-req) if not found locally. This lookup always reads directly from a frameworks include/ SOURCE directory. No build/<KEY>/ output directory is ever consulted for header resolution, at framework or workspace level -- build/<KEY>/ only ever holds obj/bin/lib/share (REQ-build-output-tree-structure), never headers. Confirms/aligns with real mkmks own behavior (see OBS-mkmk-command-phases-and-cli, OBS-mkmk-identitycard-mechanism).
