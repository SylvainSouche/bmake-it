# Cross-compilation to NetBSD is supported as a fourth cross target, alongside freebsd/linux/macos

Same --target/--sysroot mechanism as the other three, with two NetBSD-specific quirks found empirically: (1) usr/include/machine is normally created by the NetBSD installer, not shipped in the raw comp.tar.xz release set -- must be created manually as a symlink to the arch-specific header subdir (e.g. usr/include/aarch64) or <sys/cdefs.h> fails to find <machine/cdefs.h>. (2) unlike freebsd/linux/macos, clang's NetBSD driver support (at least in the clang-14 this was found on) does not auto-add the sysroot's usr/lib to the linker search path from --sysroot alone -- ld.lld reports "unable to find library -lc" even though usr/lib/libc.so genuinely exists; needs an explicit -L${BMK_NETBSD_SYSROOT}/usr/lib. The sysroot itself is built from NetBSD's own freely-redistributable release sets (base.tar.xz + comp.tar.xz, the same official-OS-artifact pattern as FreeBSD's base.txz) -- no NetBSD host or VM needed to build it. Verified: genuine NetBSD ELF produced (file(1): 'for NetBSD 10.1', dynamically linked, interpreter /libexec/ld.elf_so). See mk/mk.toolchain.llvm.mk and tests/harness/fetch/build-sysroot-netbsd.sh.
