# Shared-library version numbering uses BSD make's own bsd.lib.mk conventions (e.g. SHLIB_MAJOR/SHLIB_MINOR-style macros), producing libfoo.so.X.Y with the standard symlink chain, rather than a project-invented scheme

Resolves the versioned-naming-mechanism open question from REQ-versioned-output-naming-req: adopt real BSD make's bsd.lib.mk versioning macros (SHLIB_MAJOR, optionally SHLIB_MINOR) in mk.lib.mk, producing versioned shared-library output (libfoo.so.MAJOR.MINOR with the usual libfoo.so / libfoo.so.MAJOR symlink chain on ELF-based *NIX targets), consistent with CON-use-bsdmake's principle of reusing bsd.*.mk infrastructure rather than reinventing it. Open follow-up: macOS's Mach-O dylib versioning uses a structurally different mechanism (install names, compatibility/current version fields via the linker, not a SHLIB_MAJOR-style symlink chain) -- how mk.lib.mk reconciles that with the FreeBSD-style macro is not yet worked out.
