# A workspace/framework/module's own mk/ directory is part of the .include search path at that level and every level nested inside it (workspace: WS/mk; framework: WS/mk + FW/mk; module: WS/mk + FW/mk + MOD/mk), with WS/mk's search extended to every PARENT_WS's own mk/ directory

Open question, not yet settled: does a file in one of these mk/ directories get included automatically (Bmake It itself pulls in whatever's present, e.g. by convention filename or glob), or does it only become resolvable for an explicit .include a user writes in their own makefile (search-path extension only, opt-in)? The stated use case (a module needing extra CFLAGS without modifying core files) fits automatic pickup more naturally, but this needs to be confirmed before implementation, not assumed.
