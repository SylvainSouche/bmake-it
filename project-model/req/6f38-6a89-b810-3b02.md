# Cygwin and WSL are supported build hosts, treated as *NIX-like environments; no native MSVC/Windows-toolchain support is required

Extends CON-cross-platform-targets: in addition to macOS (MacPorts), Linux, and *BSD, Cygwin and WSL are supported build hosts. Both are treated as *NIX-like for toolchain and naming purposes (bsd make, gcc/llvm). Native Windows (MSVC/cl.exe) build-host support is out of scope. Open follow-up: REQ-output-naming-os-conventions currently distinguishes Windows naming (NAME.exe, no lib prefix) from *NIX naming -- needs revisiting to clarify whether that still applies under Cygwin (which conventionally still produces .exe) or whether Cygwin/WSL should simply follow the *NIX naming branch outright.
