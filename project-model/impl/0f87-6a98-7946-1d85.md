# mk.common.mk: make run PROGRAM=<name> ARGS=<args> -- sets the platform dynamic-lib search path to include the workspace's build/<KEY>/lib/, execs build/<KEY>/bin/<PROGRAM>, no implicit build

<!-- rationale, detail, alternatives considered -->

Originally implemented in mk.workspace.mk (workspace-root-only). Moved to
mk.common.mk -- included by all four role files (workspace/framework/prog/lib)
-- per run-target-any-workspace-dir-req: the recipe now walks up from
`.CURDIR` looking for the nearest ancestor `makefile` that `.include`s
`mk.workspace.mk`, then re-execs `make -C <that dir> run PROGRAM=... ARGS=...`
so PROGRAM=/ARGS= always resolve against the workspace's own aggregated
bin/lib (where copy-up already collected every framework's outputs),
regardless of which role directory `bmake run` was invoked from.

Moving the target into common.mk surfaced a real bmake default-goal bug:
common.mk is `.include`d before any role file defines its own `all:`, so
`run:` -- being the first target rule bmake would encounter -- silently
became the default goal for a bare `bmake` invocation, breaking two existing
test cases (28, 29) that call plain `bmake` expecting `all`. Fixed with an
explicit `.MAIN: all` in mk.common.mk.

Verified via tests/cases/31-run-target (run from workspace root,
framework dir, and module dir; ARGS= passthrough; missing-PROGRAM= and
nonexistent-program error paths) and the full 31-case suite (no regressions).
