# mk.test.mk: TESTS_CXX=/TESTS_C=/TESTS_SH= declarations compiled/staged against atf-c++/atf-c, Kyuafile generation, kyua test + report-junit/report-html

Verified end-to-end 2026-09-15 against MacPorts atf 0.21 / kyua 0.14.1, using
the Hello/libgreet.m example module's real atf-c++ test (greet_test): build,
link, kyua run, JUnit XML, and HTML report all confirmed, on both a passing
and a deliberately-failing test case (checking `bmake test`'s exit code
actually reflects pass/fail, not just that files got written).

Two real bugs surfaced and were fixed during this pass, not speculative:
- `kyua report-junit`/`report-html` take `--output=`, not `-o` (draft used
  the wrong flag spelling).
- `bmake test`'s original draft swallowed `kyua test`'s exit code with
  `|| true` so it always exited 0 even on real failures -- fixed to capture
  and propagate the real exit code while still always writing the report
  (see shared-lib-runtime-loadable-req and atf-cxx-libcxx-autoptr-gap-obs
  for the two other real bugs this pass found, in the shared-lib linking
  and MacPorts atf-c++/libc++ toolchain pairing respectively).

Extended 2026-09-16: only ever exercised against a LIB module until this
pass added a test to a PROG module (Hello/hello.m) as part of building a
multi-framework sanitizer-catch example. The link recipe unconditionally
appended `-l${LIB}`, which degenerates to a bare, broken `-l` when LIB is
undefined (PROG= modules have no such macro). Fixed: a LIB module still
links `-l${LIB}` as before; a PROG module instead links its test directly
against its own already-built objects, `${OBJS:N*/main.o}` -- excluding
main.o so the test binary supplies its own main via
ATF_INIT_TEST_CASES/ATF_TP_ADD_TCS rather than colliding with the
module's entry point. Verified against a real atf-c++ test on hello.m
(a deliberate UBSan-catchable signed-integer-overflow) alongside a LIB
module's atf-c test (a deliberate ASan-catchable heap-buffer-overflow) in
the same workspace run.
