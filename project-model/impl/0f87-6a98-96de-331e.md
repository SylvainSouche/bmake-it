# mk.prog.mk/mk.lib.mk: toolchain-agnostic win-target output naming shared by all three tiers -- PROG gets a .exe suffix (even when explicitly given, since it's a hard platform requirement not a convention), shared libs become LIB.dll + LIB.lib import lib (via -Wl,--out-implib, translated per-toolchain), static libs become LIB.lib; the redundant symlink+bonus-static-archive steps that exist for Unix targets are skipped for win since the import lib IS the .lib a consumer links against, and duplicating it as a plain static archive would silently overwrite it; the link-time not-yet-built guard's existence check also recognizes .lib
