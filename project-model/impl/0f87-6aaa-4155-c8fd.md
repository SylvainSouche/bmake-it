# mk.common.mk: SANITIZE= parses to -fsanitize=, mutual-exclusion fail-loud for address/thread/memory, MSVC restricted to address (translated by msvc-cc-wrapper.sh); composes with run/test via shared CFLAGS/CXXFLAGS/LDFLAGS

Extended 2026-09-16 after building a real multi-framework/multi-module
sanitizer-catch example (see impl-test-workspace-aggregation) surfaced
two genuine gaps the original single-module verification hadn't hit:

- **UBSan's default is non-fatal**: a deliberate signed-integer-overflow
  test case still reported "passed" under SANITIZE=undefined -- the
  diagnostic just sat in stderr, unnoticed. Fixed with
  `-fno-sanitize-recover=undefined` whenever `undefined` is requested,
  so a UBSan hit aborts on first violation the same way ASan already
  does by default. Without this fix, SANITIZE=undefined could not
  actually catch anything in a `test`/CI context.
- **`SANITIZE=` wasn't forwarded through workspace/framework recursive
  builds**: `_build_frameworks` (mk.workspace.mk) and `_build_modules`
  (mk.framework.mk) explicitly list which macros to forward to each
  `${MAKE} -C ...` sub-invocation, and SANITIZE= was missing from both
  lists -- a `bmake all SANITIZE=address` from the workspace root
  silently built every module unsanitized. Fixed by adding it to both
  forwarding lists.

Also: mk.test.mk's link recipe assumed a LIB module (`-l${LIB}`) --
untested against a PROG module until this pass added one, where LIB is
undefined and the flag degenerates to a bare, broken `-l`. Fixed there
(see mk.test.mk's own IMPL) rather than here, but found in the same
verification pass.
