# atf-bmk self-test (scripts/atf-selftest.sh), ATF_BMK_MODE=win (mingw-w64,
# MSVC): every result of ATF 0.23's own tests that differs from a pass, with
# the reason. Format: see posix.txt. Anything not listed must pass; a listed
# line that no longer happens fails the self-test too, so this list is kept
# exact as the port grows.
#
# Four causes, each a feature of a native Windows runtime, not a defect of
# the port (2026-10-30, mingw-w64 with clang):
#
#  [fork]     Starting a process (atf_process_fork: atf_check_*, atf::check,
#             atf::process, and ATF's own test helpers run_h_tc/build_check,
#             which run each case in a child) is not available yet: it fails
#             with "Running a program ... is not available in Bmake It's ATF
#             for native Windows runtimes yet". A C++ caller throws it; ATF
#             lets an exception escape a test body, which aborts (exit code 3
#             here, SIGABRT on POSIX -- upstream does the same).
#  [signal]   No POSIX signals: kill() fails, abort() ends with exit code 3,
#             not SIGABRT.
#  [perms]    No POSIX permission bits or owners.
#  [posix]    The test itself calls a POSIX-only function (fork, chown,
#             geteuid, sys/resource.h): not built.
#
# ATF's tests of the check macros (macros_test) are [fork]: atf-bmk's own
# tests (contrib/atf-bmk/tests) cover the macros on Windows instead.
